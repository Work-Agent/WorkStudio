# 架构设计

> WorkStudio 是一个以文件为中心、原生视图承载界面的桌面工作台。本文件描述目标架构：主进程负责状态、资源、页面与视图；渲染层只消费投影并发送命令；AI 会话交给 pi 运行时。

## 一、总体设计

### 1.1 状态作用域是外层，实现分层在作用域内

架构按**状态作用域**封装：

- AppScope：应用级状态与服务
- WorkspaceScope：当前工作区状态与服务
- SessionScope：当前会话运行时与上下文

每个作用域内部再按实现层组织：

```text
Scope 边界
├─ 装配：该作用域的创建、依赖注入、生命周期
├─ 域服务：该作用域共享的状态与端口
├─ 能力：该作用域需要的业务能力
└─ 存储：该作用域的持久化
```

层不是全局单例图；同一能力在不同作用域可以有不同实例。跨作用域只通过父作用域注入的端口访问，不允许直接拿到另一个作用域的全局对象。

### 1.2 总体图

```
┌─ 渲染层 ───────────────────────────────────────────────────────────┐
│ 壳层 DOM · 列表宿主 · 系统页面                                      │
│ 只持投影，无 Node                                                   │
└───────────────────────────────────────────────────────────────────┘
                            │ preload 契约桥
                            │ 命令 · 快照 / 事件 · 页面数据面 · 视图总线
                            ▼
┌─ AppHost：外部统一边界 / 编排态 ───────────────────────────────────┐
│ 当前活动 WorkspaceScope · workspace/session epoch                   │
│ 快照拼装 · 命令路由 · 事件出口                                      │
│                                                                      │
│  ┌─ AppScope ─────────────────────────────────────────────────────┐ │
│  │ 装配：应用服务 · 工作区列表 / 当前选择 · 系统视图               │ │
│  │ 域服务：App 级共享端口                                          │ │
│  │ 能力：插件 · 设置 · 浏览器 · Pi 包                              │ │
│  │ 存储：agentDir · 凭证 · 全局设置                                │ │
│  └──────────────────────────────┬─────────────────────────────────┘ │
│                                 │ 创建 / 切换 / 销毁                 │
│  ┌─ WorkspaceScope ─────────────▼─────────────────────────────────┐ │
│  │ 装配：工作区作用域与依赖                                        │ │
│  │ 域服务：ViewHost · UiState · Interaction · EventBridge           │ │
│  │ 能力：URA 实例 · 列表 · 浏览器站点 / 快照                       │ │
│  │ 存储：workspace.json / ui-state / settings / sessions 索引       │ │
│  └──────────────────────────────┬─────────────────────────────────┘ │
│                                 │ 当前会话                           │
│  ┌─ SessionScope ───────────────▼─────────────────────────────────┐ │
│  │ 适配：SessionAdapter · 扩展 UI 上下文                           │ │
│  │ 能力：runtime · Harness · tools                                 │ │
│  │ 存储：由 pi 管理的会话 JSONL                                    │ │

└─────────────────────────────────┼───────────────────────────────────┘
                                  │ 官方扩展点
                               pi SDK
```

### 1.3 关键决策

- **作用域封装实现层**：层回答“职责与依赖方向”，作用域回答“状态归谁、何时销毁”；层在作用域内部生效。
- **AppHost 只编排**：持有当前活动作用域与 epoch，负责快照、命令、事件和切换事务；不持业务真相。
- **外部统一、内部不扁平**：渲染层只面对 AppHost；AppScope / WorkspaceScope / SessionScope 各自保留装配、域服务、能力与存储边界。
- **内容走原生视图**：壳层 DOM 只画 chrome；文档、网页、插件页、助手内容由原生视图承载。
- **资源统一走 URA**：人、页面、AI 都拿同一套资源标识；格式与出口由注册表决定。
- **安装即信任**：扩展、技能、插件只从 App 私有目录装载；不引入 project trust。

## 二、状态作用域

### 2.1 三级状态

| 作用域        | 生命周期   | 拥有                                                                                       | 持久化                                                                                    |
| ------------- | ---------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| **App**       | 进程       | 模型目录、凭证、插件安装、Pi 包、全局设置、URA 绑定、系统视图、窗口集合、工作区列表        | 数据根下的 `settings.json` / `models.json` / `auth.json` / `ura-bindings.json` / `plugins/` |
| **Workspace** | 打开工作区 | 项目设置、资源地图、列表、标签视图集合、UI 现场、页面 / 写会话、会话索引、浏览器策略        | `workspaces/<wsId>/`（`workspace.json`、`ui-state.json`、`settings.json`、`sessions/`）    |
| **Session**   | 一个会话   | pi runtime、消息、轮次、流式、队列、上下文快照（资源地图版本、AGENTS、技能激活）           | 工作区内的 `sessions/*.jsonl`                                                             |

- **持久化的目录归属见 §2.6**：数据根、命名规则与可删除性。
- **工作区列表归 App**：列表不随当前工作区销毁，App 负责工作区集合与窗口绑定。
- **Workspace 整体替换**：切换工作区 = 销毁旧 Workspace 作用域，创建新实例。
- **Session 归 pi**：WorkStudio 只持当前会话的投影，不维护第二套会话状态机。

### 2.2 AppHost

AppHost 是装配层中的**状态所有者与组合根**，持有编排态：

- 当前 WorkspaceScope 指针（工作区选择由 AppScope 持有）
- `workspaceEpoch` / `sessionEpoch`
- 快照、命令、事件出口
- 工作区切换事务

它不持有 AppScope / WorkspaceScope / Session 的业务真相。

```text
AppHost
├─ AppScope        应用级状态与服务
├─ WorkspaceManager → WorkspaceScope
└─ SessionAdapter → pi SDK
```

### 2.3 纪元与切换

```ts
interface ScopeEpochs {
  workspace: number; // 工作区切换 ++
  session: number; // 会话切换 ++
}
```

- 渲染层收到旧 epoch 的事件直接丢弃。
- 工作区切换：`workspaceEpoch++`，同时进入新会话，`sessionEpoch++`。
- 会话切换：只递增 `sessionEpoch`；不重建工作区、不重载资源。

**工作区切换流程**

1. 刷新当前 UI 现场。
2. 销毁旧 WorkspaceScope：标签视图、页面会话、写会话、派生任务。
3. 注册并加载新工作区。
4. 创建新 WorkspaceScope。
5. 重建 pi runtime 的 workspace cwd 与资源根。
6. 广播新快照。

**会话切换流程**

1. pi runtime 切换到目标会话。
2. 重新绑定事件桥与扩展 UI 上下文。
3. 应用该会话的技能激活集。
4. `sessionEpoch++`，广播会话切片。

### 2.4 作用域释放

| 作用域    | 释放内容                                        |
| --------- | ----------------------------------------------- |
| Workspace | 标签视图、页面会话、写会话、UI 监听器、派生任务 |
| Session   | 事件订阅、对话框宿主、运行时上下文              |
| App       | 窗口关闭时统一释放；跨工作区服务常驻            |

### 2.5 资源加载分级

| 对象        | App                | Workspace                | Session            |
| ----------- | ------------------ | ------------------------ | ------------------ |
| 扩展 / 技能 | 全局安装           | 工作区默认与启用策略     | 激活集             |
| 页面        | 页面代码与静态资源 | 页面实例、页面会话、偏好 | 只引用资源 ref     |
| 资源        | App 私有全局根     | 工作区资源根             | 当前轮次的资源快照 |

- 目录全部在 App 私有数据目录；不读写 `~/.pi` 或真实工作区 `.pi`。
- 装载在 App / Workspace，激活在 Session。
- 扩展集合在会话创建 / 工作区切换时装配，会话内不做热开关。

### 2.6 存储布局

持久化只有一个数据根，根内按 **pi 原生 / 应用扩展** 两类组织：pi 有的概念一律沿用 pi 的位置与命名，应用只新增 pi 没有的概念。

**根**：按 `--data-dir` → `WA_DATA_DIR` → 便携目录 → 系统默认位置 的优先级解析，解析后立即让平台缓存、日志与实例锁跟随同一根，避免数据与缓存分离。

```text
<data-root>/                     pi 的 agent dir
│
│  pi 原生 —— 原样使用，应用不改其内部结构
├── settings.json                用户级设置（含 pi 包声明、会话目录覆盖）
├── keybindings.json
├── mcp.json
├── models.json
├── auth.json
├── AGENTS.md · SYSTEM.md · APPEND_SYSTEM.md
├── extensions/                  用户扩展
├── skills/                      用户技能
├── prompts/                     提示模板
├── themes/                      主题
│
│  应用扩展 —— 命名沿用 pi 风格
├── windows.json                 窗口恢复清单（上次打开的工作区集合）
├── ura-bindings.json            资源管道路由表
├── logs/
│   └── boot.log                 启动诊断
├── plugins/
│   ├── installed/<id>/          已安装视图插件
│   ├── installed.json           安装索引
│   ├── staging/                 安装解压沙盒（目录常驻，内容瞬态）
│   ├── data/<id>/settings.json  插件自持设置
│   ├── catalog.md               社区目录缓存
│   └── catalog-url.txt          目录源地址
└── workspaces/<wsId>/           一个工作区 = 一个窗口的现场
    ├── workspace.json           路径与打开时间
    ├── ui-state.json            标签 / 侧栏 / 面板宽 / 浮动几何
    ├── settings.json            项目级设置与工作区策略
    └── sessions/                会话记录
```

| 规则                             | 说明                                         |
| -------------------------------- | -------------------------------------------- |
| 沿用 pi 的位置与命名             | 设置、模型、凭证、扩展、技能、提示模板、主题 |
| 单例内容平铺为 `<内容>.json`     | 与 pi 的模型 / 绑定类配置文件同构            |
| 集合内容收为 `<复数>/`           | 与 pi 的扩展 / 技能目录同构                  |
| 应用概念不与 pi 概念同名         | 视图插件与 pi 扩展并列而非合并               |
| 子系统前缀只用于消歧             | 根上已有按键绑定文件时，不裸用通用名         |

| 数据                         | 作用域    | 格式 owner | 删除后果                         |
| ---------------------------- | --------- | ---------- | -------------------------------- |
| 设置 / 模型 / 凭证 / 扩展 / 技能 | App    | pi         | 需重新配置、登录、安装           |
| 资源绑定表                   | App       | 应用       | 回落默认解析                     |
| 窗口恢复清单                 | App       | 应用       | 丢失窗口恢复                     |
| 插件安装、安装索引、插件设置 | App       | 应用       | 丢失已安装插件与其设置           |
| 目录缓存、安装解压沙盒、日志 | 瞬态      | 应用       | 无，可重新生成                   |
| 工作区描述、UI 现场、项目设置 | Workspace | 应用 + pi  | 丢失窗口现场 / 项目设置          |
| 会话记录                     | Session   | pi         | 丢失会话历史                     |

- **偏好寄存**：应用偏好写入两个设置文件的同名命名空间字段——用户级放主题与语言，工作区级放浏览器白名单等策略；读取链为工作区策略 > 用户级偏好 > 内置默认。
- **不存根内绝对路径**：数据文件只存工作区标识或相对路径，整个根可移动、可拷贝。
- **路径派生集中在一处**：所有目录由根派生，业务代码不自行拼接。
- **副产物不落数据根**：站点快照、页面保存等写入用户工作区，跟随内容、可被编辑与版本管理。
- **pi 决定格式，应用决定位置**：迁移不解析、不改写 pi 的文件；版本号随各文件自带。
- **会话目录**：默认为工作区内的会话目录，用户显式配置时以其为准。

## 三、作用域内的实现分层

### 3.1 通用层序

在任一状态作用域内部，依赖方向固定：

```text
装配 → 域服务 → 能力 → 存储
```

| 层     | 负责                                         | 不负责         |
| ------ | -------------------------------------------- | -------------- |
| 装配   | 创建作用域、注入端口、生命周期               | 业务能力实现   |
| 域服务 | 该作用域共享的状态、视图宿主、事件、交互     | 具体格式与插件 |
| 能力   | 会话运行时、Harness、URA、插件、设置、浏览器 | 装配与壳层     |
| 存储   | 会话、设置、模型、凭证、用户状态、派生数据   | 状态决策       |

### 3.2 三作用域的内部分层

**AppScope**

| 层     | 内容                                      |
| ------ | ----------------------------------------- |
| 装配   | 应用服务、工作区列表 / 当前选择、系统视图 |
| 域服务 | App 级共享端口；系统视图宿主              |
| 能力   | 插件、设置、浏览器；Pi 包与全局资源       |
| 存储   | `agentDir`、凭证、全局设置                |

**WorkspaceScope**

| 层     | 内容                                                                   |
| ------ | ---------------------------------------------------------------------- |
| 装配   | Workspace 作用域创建、依赖注入、销毁事务                               |
| 域服务 | ViewHost、UiState、Interaction、EventBridge                            |
| 能力   | URA 实例、列表服务、浏览器站点 / 快照、页面 / 写会话                   |
| 存储   | `workspace.json`、`ui-state.json`、`settings.json`、会话索引、资源地图 |

**SessionScope**

| 层   | 内容                                                   |
| ---- | ------------------------------------------------------ |
| 适配 | SessionAdapter、扩展 UI 上下文、事件桥绑定             |
| 能力 | pi runtime、Harness、系统提示 / AGENTS / 技能 / 工具面 |
| 存储 | 会话 JSONL（pi 管理）                                  |

### 3.3 跨作用域规则

- **父到子**：AppScope 创建 / 切换 WorkspaceScope；WorkspaceScope 绑定 SessionScope。
- **只经端口**：子作用域只能使用父作用域注入的端口，不反向抓 AppHost 或全局单例。
- **同一能力可多实例**：URA 注册表属于 AppScope；资源地图、绑定、页面 / 写会话属于 WorkspaceScope；会话只读。
- **状态先声明作用域**：新增模块必须说明属于哪个作用域；跨作用域必须拆分。
- **释放按作用域**：WorkspaceScope 销毁释放标签、页面 / 写会话、UI 现场；SessionScope 换代重绑事件桥；AppScope 常驻。
- **依赖单向**：作用域内部装配 → 域服务 → 能力 → 存储；渲染层只依赖契约桥；pi SDK 不知道 WorkStudio。

## 四、跨进程契约

### 4.1 AppSnapshot

渲染层只持五块投影与壳层几何：

```ts
interface AppSnapshot {
  app: AppSlice; // 模型 / 凭证 / 插件 / 全局资源 / 设置
  workspaces: WorkspaceMeta[];
  workspace: WorkspaceSlice; // meta / settings / resources / lists / views / sessions
  ui: WorkspaceUiSlice; // 主题 / 侧栏 / 面板 / 助手 / 打开集合
  session: SessionSlice; // 当前会话投影
  layout: LayoutSnapshot | null;
  seq: number;
  workspaceEpoch: number;
  sessionEpoch: number;
}
```

- App 切片不随工作区切换变化。
- Workspace 切片随工作区整体替换。
- UI 切片属于 Workspace 现场。
- Session 切片随会话切换。

### 4.2 AppCommand 与 AppEvent

```ts
interface AppCommand<T = unknown> {
  scope: 'app' | 'workspace' | 'session' | 'ui';
  action: string;
  payload?: T;
}

interface AppEvent<T = unknown> {
  scope: 'app' | 'workspace' | 'session' | 'ui';
  epoch: number;
  seq: number;
  event: T;
}
```

- 命令是唯一写入口；作用域必须与命令类型匹配。
- 事件带 `scope + epoch + seq`；渲染层检测缺口后重新握手，不回放事件。
- 快照是重连后的最终真相。

### 4.3 握手与重连

```text
渲染层启动 / 重连
  → app.sync
  → AppSnapshot
  → 订阅 AppEvent
  → 后续增量
```

- 订阅先于快照，快照覆盖本地投影。
- 工作区 / 会话切换递增对应 epoch，旧事件自动失效。

### 4.4 页面数据面与视图总线

- 页面只持白名单命令与类型化视图总线；无 Node、无裸 IPC。
- 页面来源校验后映射到同一命令实现；未映射命令不存在。
- 内容投递等页面 ready；未就绪由主进程排队。
- 页面只声明入口与协议，不持视图句柄。

## 五、列表

### 5.1 模型

- 结构（定义）在 App，数据（分组 / 行）在当前 Workspace。
- 渲染层只消费 `ListSnapshot`，不查注册表。
- 分组和行都携带渲染所需 spec：字段、动作、空态、图标、色调、计数单位。

```ts
interface ListDefinition {
  id: string;
  label: string;
  section?: 'resources' | 'plugins' | 'settings' | 'hidden';
  icon?: string; // lucide 语义名或图片 URL / data URL
  tone?: string;
  unit?: string;
  countLabel?: string;
  order?: number;
  sourceScope: 'app' | 'workspace';
  itemType: string;
  fields: ListFieldSpec[];
  actions: ListActionSpec[];
  empty?: { icon?: string; text: string };
  grouping?: 'flat' | 'domain' | 'custom';
}
```

分组字段：

```ts
interface ListGroup {
  id: string;
  definitionId: string;
  section: 'resources' | 'plugins' | 'settings' | 'hidden';
  label: string;
  icon?: string;
  tone?: string;
  unit?: string;
  countLabel: string;
  updatedAt: number;
  count: number;
  state: 'loading' | 'ready' | 'error';
  fields: ListFieldSpec[];
  actions: ListActionSpec[];
  empty?: { icon?: string; text: string };
  items: ListItem[];
  diagnostics?: string[];
}
```

- `icon` 同时支持 lucide 语义名、SVG/PNG data URL、favicon URL。
- `tone` / `unit` / `countLabel` 由定义或 provider 给出，渲染层不按列表 id 写死。
- 单个 provider 失败只产生一个 error 分组，不拖垮整个快照。

### 5.2 注册与扩展

- 内置列表与插件列表共用注册面。
- 插件通过注册入口声明定义与 provider。
- Provider 只拿列表上下文：workspace、tree、find、settings、icon；拿不到视图句柄和写通道。
- 列表 provider 的归属插件由注册时的 owner 决定。

### 5.3 侧栏

- 主列表只显示分组行，不直接展开所有文件。
- 分组下显示已打开项；点击分组进入二级列表。
- 分组显示计数、最近更新时间、图标和色调。
- 已移除分组顶置能力。
- 会话列表不进入资源侧栏，会话管理归设置域。
- 收起态只显示图标列，不显示行内关闭按钮，避免误触。

### 5.4 动作

- 行激活统一发 `list.action`。
- 动作至少覆盖 open / close / pin / delete / 插件自定义动作。
- 打开文档、会话、插件页、设置页均由主进程路由，不由渲染层按 itemType 写死通道。

## 六、视图与布局

### 6.1 内容类型

| 类型     | 标识                     | 承载           |
| -------- | ------------------------ | -------------- |
| 资源文档 | 资源 ref                 | 插件页或网页   |
| 在线网页 | URL                      | 浏览器原生视图 |
| 插件页   | `settings://plugin.<id>` | 插件页面       |
| 设置页   | `settings://<id>`        | 内置页面       |

### 6.2 视图集合

- 标签 = 视图实例投影；顺序、激活、固定、脏态由主进程给出。
- 关闭当前标签时先计算邻居，再删除；集合中必须始终有有效激活项。
- 集合为空时自动打开欢迎页；欢迎页同键唯一，不进入设置列表。
- 页面会话与写会话随标签关闭释放；工作区销毁时全部释放。

### 6.3 布局不变量

主进程是几何唯一真相源；DOM 壳层和原生视图消费同一份矩形。

- 左侧把手的命中区在侧栏内部，资源内容从侧栏右边缘直接开始，不留白色让位带。
- 右侧把手的命中区在助手视图内部；资源与助手视图直接相接。
- 分隔线只画 1px，不绘制覆盖内容的表面色。
- 拖动期间布局跟指针走；松手才提交收起 / 展开。
- 原生视图覆盖 DOM；DOM 把手不能放在原生视图下面。

### 6.4 交互

- 分栏、视图移动、视图缩放、标签重排都走同一套指针交互会话。
- 主进程按 screen 光标计算预览，渲染层只看预览快照。
- Esc / 指针抬起 / 窗口失焦结束交互；结束时夹取并提交。

### 6.5 平台约束

- 窗口使用隐藏标题栏；macOS 使用系统交通灯位置，Windows / Linux 使用 WCO。
- 窗口控制、菜单、目录选择走原生能力。
- 视图 bounds 使用整数 DIP；窗口缩放与 DevTools 停靠后重新计算。

## 七、资源管道 URA

### 7.1 职责

URA 是资源内容的唯一入口：人、页面、AI 都只拿 ref，不拿物理路径或句柄。

```text
读：
ref → transport → { mime, bytes }
    → codec → document
    → store（可选）→ structured data
    → presenter（页面 / 浏览器）或 sidecar（文本 / schema）

写：
change → locate → encode → transport.commit
       → cache invalidate → data update → broadcast
```

### 7.2 分段

| 段                  | 认的标志                   |
| ------------------- | -------------------------- |
| transport           | scheme                     |
| codec               | MIME                       |
| store               | codec                      |
| presenter / sidecar | `(transport, mime, codec)` |

- MIME 只取规范值；参数作为元数据保留。
- 未识别的格式降级 raw，页面与 sidecar 明确降级点。
- 绑定表用户优先，落 App 数据目录。
- 同键写串行，后写覆盖先写。

### 7.3 会话

- 写会话：草稿 → 提交 → 分片队列；草稿不进模型上下文。
- 页面会话：与视图实例绑定；关闭视图释放。
- 资源地图：每工作区一份 AGENTS.md，由列表 / 资源数据生成并去抖重建。
- 网页旁路 URA：网页快照已是 Markdown，直接登记为文档；实时网页由浏览器视图承载。

### 7.4 列表与资源地图

- 资源地图消费当前工作区的 ListSnapshot，只收录资源 section 中有 ref 的文档。
- 资源文件变化触发 watch 与去抖重建。
- 生成内容与 codec、schema 清单同源，供 pi 的上下文入口读取。

## 八、Agent 与 Harness

### 8.1 pi 双轴

```text
资源轴（声明式）                 注册轴（命令式）
扩展 / 技能 / 设置目录           扩展模块执行时注册
        │                               │
        └──────────► pi 运行时 ◄─────────┘
```

- 资源轴只装载文件，不执行项目代码。
- 注册轴由扩展工厂在运行时填充工具、命令、钩子、provider。
- WorkStudio 不另造 Agent 插件系统。

### 8.2 会话运行时

- 每个工作区拥有一个可换代的运行时；会话切换委托 pi。
- 事件桥将 pi 事件转成线格式：`message_*`、`tool_execution_*`、`agent_settled`、内部会话事件。
- 事件合帧，`seq` 单调递增；渲染层按会话投影消费。
- AgentHost 负责模型 / 档位、队列、压缩、扩展 UI 上下文、浏览器自动化工具。
- 工作区切换重建运行时；会话切换只重绑事件桥与扩展 UI 上下文。

### 8.3 Harness

Harness 是 WorkStudio 提供给 pi 的会话侧能力，不是独立产品层：

| 部分     | 内容                                         |
| -------- | -------------------------------------------- |
| 系统提示 | 角色、边界、工作方式                         |
| 上下文   | AGENTS、资源地图、技能激活集                 |
| 工具     | URA 读写 / 检索 / 查询工具；浏览器自动化工具 |
| 钩子     | 轮次结束、资源刷新、上下文更新               |

- 技能：全局安装 → 工作区默认 → 会话激活；激活集进本轮提示。
- 扩展：全局安装 → 工作区启用；会话创建时继承，不在会话内热开关。
- 工具不直连来源，统一走 URA。

### 8.4 扩展 UI

- 对话框由主进程 DialogHost 管理，浮层视图渲染；取消 / 超时 / 会话关闭都按取消值结算。
- 扩展 UI 的编辑器回灌、状态、widget、working message 经 AppEvent 投递到助手视图。
- 通知进入工作台通知层。
- TUI 专属能力明确降级为 no-op，不伪装成桌面支持。

## 九、能力形态与扩展

### 9.1 插件

- 插件是唯一可安装形态；一个 zip 一个插件。
- 清单声明 id / label / icon / page / settings / apiVersion；图标支持语义名或文件。
- 注册入口登记 transport / codec / store / presenter / sidecar / list / view action。
- 远程必须 `.zip` + `#sha256=`；本地路径原地加载。
- 可安装清单随源码维护，构建期解析为静态数据，主进程与插件设置页共用；运行期不读、不写 Markdown。
- 安装到 App 私有插件目录；安装 / 卸载下次启动生效。
- 同 id 重复安装覆盖旧版本；不自动更新。

### 9.2 设置

- 设置页由主进程能力拥有；页面清单与入口在设置注册表。
- 页面代码走 app 协议，无 Node；只拿白名单命令。
- 插件设置页归设置面，但页面由插件提供。

### 9.3 浏览器

- 浏览器旁路 URA：实时视图直接嵌入，快照已 Markdown。
- 白名单域 = 采集域；域下页面按站点快照进入列表。
- 白名单外网页为临时标签，不落盘、不进入资源地图。
- 浏览器自动化工具供 Agent 使用；页面元素标记与快照共享同一结构。

### 9.4 Pi 包与技能

- Pi 包、扩展、技能分别安装与管理；不是 WorkStudio 插件。
- 包来自 App 私有资源目录；不读取真实工作区 `.pi`。
- 安装即信任；不引入 project trust。

## 十、渲染层

### 10.1 壳层

```text
┌ TitleBar ──────────────────────────────────────────────┐
│ 工作区 · 侧栏开关 │ 地址栏 / 工具条 │ 助手 · 主题 · W │
├ Sidebar ─┬ Resource Panel ──────────────┬ Assistant ──┤
│ 资源 /   │ TabsBar + 原生视图内容       │ 会话标签    │
│ 插件 /   │                              │ 消息流      │
│ 设置     │                              │ 输入区      │
└──────────┴──────────────────────────────┴─────────────┘
```

- 标签内容全部由原生视图承载；DOM 只画壳层与空态。
- 列表按 ListSnapshot 渲染；壳层不复制内容 UI。
- 助手是独立系统视图，输入、消息、会话标签都在其中。

### 10.2 助手

- 会话标签独立于资源标签。
- 输入区支持 slash 命令：补全、tag 化、参数输入、移除。
- 命令目录来自内置命令 + pi 扩展命令；未知 slash 命令透传 pi。
- 模型 / 思考档位 / 技能 / 会话操作在输入区工具条内完成。
- 消息流按用户 / 思考 / 文本 / 工具块渲染；工具结果可折叠。
- 流式中支持 steer / followUp 队列。

### 10.3 主题与视觉

- 亮 / 暗两套；所有派生色来自系统主题层。
- 标题栏 40px，标签栏 36px，侧栏 15%–30% 窗口宽，收起 56px 图标列。
- 分隔条只保留 1px 线；不留下白色让位带。
- 字体使用系统栈；地址与代码使用等宽字体。

## 十一、约束、失败与验收

### 11.1 依赖与边界

- 渲染层不 import 主进程；只走 preload 契约桥。
- 会话运行时不依赖 Electron 界面。
- 视图管理不碰格式、版本、写队列。
- 能力层不直接改视图集合。
- pi SDK 不知道 WorkStudio。

### 11.2 失败与降级

| 失败                     | 处理                                         |
| ------------------------ | -------------------------------------------- |
| 列表 provider 失败       | 该组 `state=error` + diagnostics；其他组继续 |
| URA 无 codec / presenter | 返回 raw + 明确降级信息                      |
| 写冲突                   | 同键串行，后写覆盖；页面收到变更提示         |
| 视图崩溃                 | 只影响该视图；壳层与其他视图继续             |
| 扩展异常                 | 记录诊断；不阻断会话                         |
| 页面未 ready             | 主进程排队投递；超时错误可见                 |

### 11.3 性能与容量

- 列表 provider 有返回上限；ListService 截断 / 分页。
- 会话历史按会话懒加载；快照不携带全量消息。
- URA 扫描有文件数与字节上限；大文件按窗口读。
- 事件合帧窗口控制 delta 体积。

### 11.4 不变量

- 单写者：状态变更经 AppHost 命令路径。
- 单快照：渲染层只持投影；重连以快照为准。
- 纪元单调：workspace / session epoch 只增不减。
- 作用域隔离：App 不持工作区数据；Workspace 不持跨工作区缓存。
- 释放完备：工作区销毁关闭标签视图、页面 / 写会话、监听器。
- 列表自包含：ListSnapshot 带渲染所需 spec。
- 空集合兜底：无标签时自动打开欢迎页。
- 私有资源根：不读写 `~/.pi` 或真实工作区 `.pi`。
- 安装即信任：不执行项目目录代码。

### 11.5 验收

**作用域**

1. 工作区切换后 App 级资源仍存在。
2. 工作区切换后旧标签、列表、页面 / 写会话、UI 现场全部消失。
3. 会话切换不重建工作区、不重载资源。
4. 旧 epoch 事件不会进入新界面。

**列表**

1. 主列表只显示分组行，二级列表显示行。
2. 分组图标 / 色调 / 计数 / 更新时间由快照给出。
3. 插件注册新列表无需改渲染层。
4. 单组失败不影响其他组。

**视图**

1. 关闭当前视图后必有有效激活项。
2. 空集合自动打开欢迎页，欢迎页唯一。
3. 展开 / 收起 / 拖拽后无白色让位带，分隔线保持 1px。
4. 资源面板内容与助手视图边界直接相接。

**助手**

1. slash 补全、tag、参数、执行、移除正常。
2. 流式中 steer / followUp 正常。
3. 扩展 UI 回灌、状态、widget 正常。
4. 会话切换后消息、队列、技能激活集正确切换。

**资源**

1. 人 / 页面 / AI 都经 URA；页面无 Node。
2. 写会话同键串行；外部变更可见。
3. 资源地图随列表与文件变更更新。

**扩展**

1. 插件 zip 安装、卸载、重启生效。
2. 注册点可扩展资源段与列表，不改壳层。
3. 设置页与插件页只走白名单命令。
