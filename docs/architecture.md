## 一、现状

### 1.1 垂直 Agent 的差异

| 维度     | Personal Agent | Coding Agent       | Work Agent（本项目）           |
| -------- | -------------- | ------------------ | ------------------------------ |
| 资料     | 少来源、云端   | 单一代码库         | 多来源、多格式、权限不一       |
| 内容     | 文本 / 会话    | 可执行、可验证     | 内容 + 数据（数据只给 schema） |
| 目的     | 完成一次任务   | 改对代码           | 在规则内完成业务操作           |
| 执行路线 | 检索 + 生成    | 生成 → 执行 → 验证 | 编排确定性工具，不生成代码     |

### 1.2 问题分析：两类代偿方案的缺口

这些碎片是工作本身的形态，不是缺陷：岗位工作天然跨来源（本地文件 / 云盘 / 业务系统 / 网页 / 邮件）、跨格式（文档 / 表格 / 网页 / 邮件 / 画布）、跨版本、跨权限、跨语境。问题在于**收敛碎片的代价**——每跨一个维度都要人定位、转换、核对、回填，动作不可复用、不可追溯，成本随任务数量线性叠加。现状的两种应对都没有降低这笔代价：不用工作台时它全部由人承担（A），用 Coding Agent 代劳时它被转换成接口错配（B）。

#### A. 不用工作台：人工在各工具之间搬运

| 环节 | 现象                                                                        | 代价                                       |
| ---- | --------------------------------------------------------------------------- | ------------------------------------------ |
| 取材 | 资料散落在本地文件、云盘、业务系统、网页、邮件，定位靠记忆与搜索词          | 找不全，也无法判断是否找全                 |
| 取材 | 下载副本、另存副本、邮件附件并存，没有权威版本标识                          | 取到旧版，改完才发现改的是过期文件         |
| 取材 | 云盘链接、系统角色、邮箱委托各成一套权限                                    | 可见性靠人工逐一确认                       |
| 理解 | docx、pdf、xlsx、邮件、网页各有专用打开方式，同一份内容在不同工具里呈现不同 | 时间花在打开与转换上，判断口径随工具变化   |
| 理解 | 转纯文本或截图后，表格关系、层级、批注、修订痕迹消失                        | 判据丢失，结论只能凭印象                   |
| 理解 | 业务数据只见界面、不见字段                                                  | 口径、取值域、关联关系靠人转述             |
| 理解 | 规则、模板、审批要求散在文档与口头约定里                                    | 每个任务重新补充，补的内容不进任何记录     |
| 执行 | 人是流程引擎，在多个界面里手工复制、比对、填写、提交                        | 步骤不可回放，换人即从头学                 |
| 执行 | 既无幂等也无串行                                                            | 重复提交产生重复记录；后写静默覆盖先写     |
| 回收 | 产物先落成文件，再由人搬回业务系统                                          | 附件名、目录位置、字段映射全靠约定口径     |
| 回收 | 导出 → 编辑 → 导入 往返                                                     | 样式、公式、超链接、修订被破坏             |
| 追溯 | 说不清结论基于哪份资料、哪一版；操作散在各系统日志里                        | 复核只能重做一遍，第二个人接手从零开始     |
| 安全 | 资料靠邮件附件、共享链接、截图在人和工具之间流转                            | 谁看过、发给了谁无从追踪；脱敏全靠人手工删 |

#### B. 用 Coding Agent 代劳：每件事都变成一次编程

Coding Agent 的形状是「一个仓库 + shell + 生成代码 → 执行 → 验证」。套到工作上，每个任务都被迫走成三段：**先生成脚本 → 再执行 → 再由人核对**。三段里没有一段是业务动作，全是开发动作。

| 阶段 | 现象                                                                       | 代价                                                           |
| ---- | -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 起手 | 任何任务都先产出一段脚本，任务还没开始，人已经进入编程                     | 改一个单元格、导一份清单这类动作，也要等脚本写完               |
| 读   | 格式解析（docx 版式、pdf 扫描件、xlsx 合并单元格、网页动态内容）由脚本自理 | 每类来源都要重写一段解析；读错不报错，结果悄悄偏了             |
| 读   | 业务字段与文档里的位置对应关系靠猜                                         | 字段映射错了，输出看着合理但不可用                             |
| 写   | 写回业务系统没有接口，脚本只能落文件或模拟点击                             | 写回不可靠；导出 → 编辑 → 导入 破坏样式、公式、修订            |
| 定位 | 失败信息是给开发者看的堆栈或异常                                           | 用户分不清错在脚本、数据，还是系统                             |
| 验证 | 没有断言，正确性靠读脚本加人工比对结果                                     | 验证成本高于自己动手；脚本本身成了必须复核的产物               |
| 复用 | 同一意图每次生成不同实现                                                   | 动作不能沉淀为工具，也无法按任务授予权限、事后审计             |
| 安全 | 数据以副本形式落进工作目录、脚本参数、会话记录与模型上下文                 | 副本失控：谁在何时读走了哪些字段，事后答不上来                 |
| 安全 | 权限只能按目录给，无法按字段、按记录收窄                                   | 要么整目录放开，要么办不了；凭证与敏感字段没有收口的通道       |
| 安全 | 脱敏与临时授权只能事前人工做，没有到期回收                                 | 一次外发不可撤回，合规检查也没有凭据                           |
| 门槛 | 判断脚本是否安全、是否会改错数据，需要编程能力                             | 普通用户全程无法确认 Coding Agent 做了什么，只能选择相信或不用 |

#### 归并

| 痛点簇                                   | 缺口的能力                                           | 对应主张                 |
| ---------------------------------------- | ---------------------------------------------------- | ------------------------ |
| A 取材、理解、回收、安全；B 读、写、安全 | 资料有唯一身份、只解释一次、写入只有一条通道         | **一条资源管道**         |
| A 执行、回收；B 写、复用                 | 唯一状态，人的操作与 AI 执行同一入口，写入不互相覆盖 | **一棵状态树、一次投影** |
| A 追溯；B 起手、定位、验证、门槛         | 内容可在原处读、改、核对，动作留痕                   | **内容表面独立**         |

五个维度不变，变的是谁来付收敛那笔代价：A 留给人，B 变成一次编程。WorkStudio 把它收进管道。

### 1.3 三条设计主张

| 主张                     | 机制                                                               | 消除的问题                       |
| ------------------------ | ------------------------------------------------------------------ | -------------------------------- |
| **一条资源管道**         | 工作区的资料统一登记、只解释一次；人、页面与 AI 共用同一条读写通道 | 多套读写、格式耦合、副本失控     |
| **一棵状态树、一次投影** | 主进程持唯一状态；手动操作与 AI 执行同一个入口；界面只消费投影     | 写覆盖、人机两套逻辑、状态不同步 |
| **内容表面独立**         | 标签内容一律原生视图，人在原处直接读、直接改、直接核对             | 壳层遮挡、验证滞后               |

## 二、领域模型

**聚合根是工作区**：它同时是隔离边界、持久化边界与换代边界。工作区之下两条主线——文件（人用面）与会话（AI 用面）——消费同一份资源。

```
Workspace（聚合根）
├─ Files 文件
│   ├─ 分组 / 目录 / 查找（派生，可重建）
│   └─ 文档：查看 · 编辑 · 保存 · 检索 · 订阅
├─ Sessions 会话
│   ├─ 上下文：系统提示 · 资源地图 · 技能选中集
│   ├─ 消息与工具调用（真相在 pi）
│   └─ 运行时：流式 · 队列 · 模型档位
├─ Scene 现场：主题 · 栏宽 · 打开集合键 · 助手形态
└─ View collection 打开集合：标签顺序 · 激活位 · 固定位

横向能力
├─ 插件：资源实现 + 页面 + 集合 + 动作
├─ 设置：内置页面清单
└─ 浏览器：在线网页 + 自动化
```

| 实体       | 标识                             | 真相源                | 持久化            |
| ---------- | -------------------------------- | --------------------- | ----------------- |
| 工作区     | 路径                             | 工作区注册表          | 自描述文件        |
| 资源       | ref（scheme + authority + path） | 来源                  | 来源侧 + 派生层   |
| 会话       | 会话文件                         | pi 会话管理器         | 会话文件          |
| 插件       | 插件 id                          | 插件清单              | 插件根 / 安装目录 |
| 页面       | 插件 id 或设置页 id              | 插件清单 / 设置注册表 | 页面文件          |
| 模型与配置 | provider / model id              | pi 设置与凭证链       | 设置文件          |

## 三、产品形态

同一份资源有三种主语：文件说「我有什么」，会话说「我要做什么」，插件说「我有哪些能力」。三者不平权——会话不持有数据，插件不持有身份与状态，也不直接执行——所以定下主视角，产品形态就同时定了：

| 主视角 | 角色   | 产品回答的问题                 | 形态       | 另外两个的位置           |
| ------ | ------ | ------------------------------ | ---------- | ------------------------ |
| 文件   | 人     | 我有什么资源，用怎样的过程处理 | **Studio** | 会话是过程，插件是扩展   |
| 会话   | AI     | 我要做什么，过程中取哪些资料   | Chat       | 文件是上下文，插件是工具 |
| 插件   | 扩展者 | 我有哪些能力，能拼出什么桌面   | 虚拟桌面   | 文件与会话都只是能力窗口 |

三条路都成立，服务的工作不同。本项目选 Studio：

1. **产物是资料，不是对话**。岗位工作交付的是文档、表格、系统里的记录；对话可以丢，产物必须留。以会话为主视角，交付物还得从上下文里二次搬出去。
2. **核对只能发生在对象上**。正确性靠人在最终产物上确认；只有文件在场，才谈得上同一份、可回读、可实时核对，不必在过程记录里推断。
3. **扩展不能污染状态**。以插件为主视角，产品退回能力窗口的集合，文件与会话被各能力瓜分。

代价是产品比聊天框重：要有工作区、原生视图、本地文件与系统集成，「AI 在真实资料上动手、人当场核对」才成立。

结论：主视角是文件，会话是过程，插件是扩展，产品只能是 Studio。

## 四、整体架构

```
┌─ 渲染层 ────────────────────────────────────────────────────────┐
│ 壳层 DOM：标题栏 · 侧栏 · 标签栏 · 空态                          │
│ 系统页面：助手 · 浮层 · 指针捕获层                               │
└──────────────────────────┬──────────────────────────────────────┘
                           │ preload 契约桥：白名单命令 / 快照 / 事件
┌─ 主进程 ─────────────────▼──────────────────────────────────────┐
│ 装配层：生命周期 · 窗口 · 协议 · 命令路由 · 域服务装配            │
├─────────────────────────────────────────────────────────────────┤
│ 域服务：会话宿主 · 视图宿主 · 状态树 · 事件桥 · 交互控制          │
├─────────────────────────────────────────────────────────────────┤
│ 能力层：                                                         │
│   URA        transport → codec → store → consumer                │
│   Harness    系统提示 · 技能 · 7 个资源工具 · 浏览器工具          │
│   插件        注册面 + 页面                                      │
│   设置        settings.list + 内置页面                           │
│   浏览器      https 来源 · WebContentsView · 自动化 · 快照        │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 官方扩展点
┌─ pi SDK ─────────────────▼──────────────────────────────────────┐
│ 模型 API · 轮次循环 · 会话持久化 · 资源装载 · 扩展运行器          │
└─────────────────────────────────────────────────────────────────┘
```

- **views 只消费契约**：页面解析、页面会话、变更订阅、命令；不碰格式、版本、写队列。
- **main 分层**：装配层（组合根）→ 域服务（状态与生命周期）→ 能力层（URA / harness / 插件 / 设置 / 浏览器）。
- **会话是域服务单位**：一个会话携带自己的上下文、工具集与运行时；会话换代 = 子树替换。
- **扩展不是一层**：插件由主进程装载并注册进 agent；页面在沙箱里运行。
- **依赖单向**：views → agent → pi；agent 不依赖 Electron，views 不依赖 pi。

## 五、核心模块

### 5.1 三类承载：一条资源管道的三种方式

插件、设置、浏览器不是三套设施，而是同一条资源管道的三种接入方式：差别只在谁拥有代码与生命周期，以及从管道的哪一段接进来。框架核心只内建 `file` / `http` / `https` 三种来源，其余来源与格式由插件注册。

| 承载       | 接入管道的方式                                        | 拥有者与生命周期   | 扩展方式               |
| ---------- | ----------------------------------------------------- | ------------------ | ---------------------- |
| **插件**   | 注册 transport / codec / store / consumer，并自带页面 | 安装者：可装可卸   | 对外开放的唯一扩展形态 |
| **设置**   | 只占页面出口：框架自带页面，不经 codec / store        | 框架：随版本发布   | 框架内新增一页         |
| **浏览器** | 内建 https 来源与实时呈现层，附带自动化与快照         | 框架：不随内容变化 | 内建，不逐站配置       |

```
┌────────────────────────── WorkStudio ──────────────────────────┐
│                                                                │
│  插件                         设置                  浏览器      │
│  可安装包                     内置页面              内建运行时  │
│  ┌──────────────┐          ┌──────────────┐      ┌───────────┐ │
│  │ 注册面 + 页面 │          │ settings.list │      │ 在线网页  │ │
│  │ URA 实现      │          │ app://page    │      │ 自动化    │ │
│  └──────┬───────┘          └──────┬───────┘      └─────┬─────┘ │
│         │                         │                    │       │
│         └───────────┬─────────────┴────────────┬───────┘       │
│                     ▼                          ▼               │
│               URA 资源管道              页面与视图宿主          │
└────────────────────────────────────────────────────────────────┘
```

### 5.2 URA：一条资源管道

```
读：
ref ─► transport ─► RawContent{mime, bytes, formatHints}
    ─► binding(transport, mime, intent) ─► codec ─► 文档 + docType ─► store ─► 可查询数据
    ─► binding(transport, mime, intent) ─► presenter
           ├ page    ─► 插件页面
           ├ browser ─► 内建实时视图
           └ sidecar ─► 文本 / schema

各段由谁提供：
transport   内置 file / http / https；插件可新增或覆盖
codec/store 插件（含内置插件）
presenter   page 由插件提供，browser 由框架提供
sidecar     插件；未注册时回退通用文本投影

选择顺序：绑定 ─► MIME ─► formatHints ─► raw

写：
变更 ─► 定位 ─► 编码（最小补丁） ─► 来源提交 ─► 数据更新 ─► 广播
```

| 段         | 职责                                                            |
| ---------- | --------------------------------------------------------------- |
| transport  | 协议 → RawContent（mime、bytes、formatHints）；能力在注册时声明 |
| codec      | RawContent → 文档 + docType；hints 只参与选择，不参与解释       |
| store      | docType → 结构化查询                                            |
| consumer   | docType × 出口 → 文本 / 页面入口 + 数据                         |
| collection | 侧栏分组                                                        |
| action     | 地址栏动作                                                      |

关键决策：

- **ref 是身份**：`scheme://authority/path`；不带格式、意图、表现层。
- **MIME 是格式身份**：transport 返回规范 MIME 与字节；codec 注册自己可解析的 MIME；不嗅探字节，未知时回退 hints / 扩展名 / raw。
- **绑定解决冲突**：`(transport, mime, intent)` 同时选择 codec 与 presenter，是一张可配置的表；不同 transport 的同一 MIME 可以绑定不同实现（如 `https + text/html → 浏览器`，`file + text/html → HTML 阅读器`）。
- **LLM 读取面是 sidecar**：不参与表现层竞争，始终把文档 / 原始字节转成文本或 schema，供 `read`、检索与上下文使用。
- **冲突由绑定解决**：默认按 MIME 与来源选择实现，用户可写入 `(transport, mime, intent)` 绑定覆盖；绑定配置在应用数据目录，启动时加载。
- **读写同一门面**：AI 工具、页面、命令都走同一实现；写经过草稿 → 提交 → 分片队列，后写覆盖先写。
- **失败降级 raw**：任一环缺失都返回原始内容与兜底页，并记录降级点。

### 5.3 状态树与现场

```
workspace（聚合根）
├─ files / groups          持久：来源为真值，索引可重建
├─ sessions/<id>           隔离：context · tools · messages · runtime
├─ scene                   持久：主题 / 栏宽 / 打开集合键 / 助手形态
└─ ui                      viewCollection · sidebar / layout · overlays

派生：resourceMap · AGENTS 投影 · 结构化数据 · 页面缓存
外部：pi 会话 · 资源内容 · 插件清单
```

- **一条通道**：命令 → 事务 → 快照 / 事件。
- **派生可重建**：删掉派生层不影响真相；重建期间读走直通。
- **会话隔离**：会话子树互不引用；换代只替换该子树。
- **上下文是投影**：AGENTS.md、资源地图、工具集都从 URA / pi 装载生成，不旁路读文件。

### 5.4 视图与页面

| 表面   | 承载                                      | 生命周期       |
| ------ | ----------------------------------------- | -------------- |
| 壳层   | DOM（标题栏 / 侧栏 / 标签栏 / 空态）      | 主窗口         |
| 助手   | WebContentsView                           | 单例，随窗口   |
| 内容页 | WebContentsView（插件页 / 设置页 / 网页） | 标签集合       |
| 浮层   | WebContentsView                           | 单例，按需显示 |
| 捕获层 | WebContentsView                           | 常驻预热       |

- **视图宿主独占**：创建、几何、层级、焦点与销毁都在主进程。
- **布局单轨**：主进程计算全部矩形；渲染层只上报视口与画 chrome。
- **页面会话**：打开 → 就绪 → 投递 → 脏态 / 提交 → 释放；页面只持白名单桥。
- **三种内容**：设置页、插件页、在线网页；都由视图宿主统一装载。

### 5.5 插件与安装

插件是 npm 包：`package.json` 的 `workstudio` 字段声明 id / label / icon / page，`exports["./ura"]` 指向 ESM 注册入口。

```
安装来源                    落盘                         装载
npm:<pkg>@<ver>   ─┐
git:<repo>@<ref>  ─┼─► 插件安装目录 ────────────────────┐
本地路径           ─┴─► 原地加载（不复制）              ├─► 扫描清单 → import ./ura → 注册 → 建页面
                                                       ┘
```

- **唯一插件形态**：可注册资源实现并自带页面的 npm 包。
- **一次装配**：启动时扫描并注册；安装 / 卸载后重启生效。
- **注册即代码**：模块求值时调用 `registerXXX`，不需要额外的 manifest 描述贡献点。
- **页面白名单**：插件页只能装载自己目录下的资源。

### 5.6 设置：主进程内置页面

- 设置页清单与页面都由主进程拥有，页面目录与插件页分开；
- `settings.list` 投影清单，`views.open({ type: 'settings' })` 打开；
- 页面与插件页共用 `app://page`、preload 桥、主题广播与会话生命周期；
- 设置页不参与安装、版本与信任流程，新增设置 = 加一页 + 一条清单。

### 5.7 浏览器：在线内容的统一侧车

```
实时：
URL ─► 视图宿主：WebContentsView 直接导航（共享浏览器 session）
    ─► 工具：browser_open / read / click / type / back / screenshot / snapshot

归档与读取（不在打开路径上）：
URL ─► https transport ─► codec ─► Markdown 快照 / sidecar 文本
```

- 实时视图不经管道：打开只做导航，不预取内容、不解码；transport 与 codec 只在归档、快照与 agent 读取时发生。
- 网站没有逐站插件配置；transport、codec、render 都是框架固定实现。
- 插件注册的 codec 仍可全局命中网站响应；浏览器本身不提供逐站 adapter。
- 白名单只控制「是否归档 / 是否临时标签」，不影响能否访问。
- 本地 HTML 等资源仍走插件页面，只有 `live` 能力才选择浏览器表现层。

### 5.8 pi 接入

```
启动
 ① 设置与凭证
 ② 系统提示（角色 / 资源地图 / 数据轨）
 ③ 资源装载（extensions / skills / prompts / themes）
 ④ 会话服务（模型运行时 + 资源装载器）
 ⑤ 会话（停用 pi 内置工具，注册 harness 工具）
```

pi 提供模型、轮次、会话持久化与扩展运行器；WorkStudio 提供 L2/L3：资源管道、工具、提示、页面与桌面壳层。

### 5.9 三方边界：URA / Agent / 插件

| 维度   | URA（框架）                                          | Agent（pi + harness）        | 插件                                                                                         |
| ------ | ---------------------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------- |
| 拥有   | ref、绑定表、写队列、页面会话、派生索引              | 会话、轮次、上下文、工具编排 | 管道中的某一段实现（transport / codec / store / consumer / presenter / sidecar）与自己的页面 |
| 不拥有 | 内容本身（真相在来源）                               | 资源实现、页面、状态树       | ref 身份、绑定表、写队列、别的段与别人的页面                                                 |
| 入口   | 门面：read / write / edit / grep / find / ls / query | 7 个资源工具 + 浏览器工具    | SDK 注册，装载时求值                                                                         |
| 出口   | 文本 / schema / 页面入口 / 实时视图                  | 消息与工具调用（真相在 pi）  | 页面投影 + 白名单命令                                                                        |

- **只经门面**：agent 与页面都不碰文件系统与来源协议；插件实现被门面调用，不反向驱动 agent。
- **身份不外包**：ref、绑定、写队列、脏标记归框架；插件只声明能处理什么（MIME / hints / docType），不新建身份空间。
- **页面不越界**：插件页没有 Node，不直连 pi，只拿投影与白名单命令。
- **能力经工具暴露**：插件不给模型加代码执行；能力以确定性工具与命令出现，agent 只编排。
- **实时视图直连**：浏览器由视图宿主直接导航，不走 transport / codec；管道只服务归档与 agent 读取。

## 六、通讯

| 通道        | 方向          | 语义                                            |
| ----------- | ------------- | ----------------------------------------------- |
| 命令        | 渲染 → 主进程 | 唯一写路径：`域.动作` + 信封 → `ok/data` 或错误 |
| 握手        | 渲染 → 主进程 | 订阅 → 快照 → 覆盖本地投影                      |
| 事件        | 主进程 → 渲染 | 单调序号事件帧；高频增量合帧                    |
| 状态 / 视图 | 主进程 → 渲染 | 壳层与视图集合快照                              |
| 页面数据面  | 页面 → 主进程 | 白名单命令，转发同一实现                        |
| 视图总线    | 双向          | 投递 / 就绪 / 脏态 / 提交 / 动作 / 主题         |
| 交互        | 渲染 → 主进程 | 拖拽信号与预览；几何由主进程裁决                |
| 原生能力    | 渲染 → 主进程 | 打开路径 / 外链 / 菜单 / 目录选择               |

```
命令 ──────────────────────────────► 主进程
快照 / 事件 / 状态 ◄─────────────── 主进程
页面 ◄── 投递 / 主题 ── 主进程 ── 就绪 / 脏态 / 提交 ──► 页面
```

- 握手保证「订阅先于快照」，缺口用重新握手恢复，不做增量回放。
- 页面只持有语义桥：白名单命令 + 视图总线；无 Node、无裸 IPC。
- 会话域命令以会话为边界；文件与视图命令属工作区级。

## 七、生命周期

```
① 工作区解析（注册表 / 默认工作区 / 最近打开）
② 插件扫描与注册（来源 → 清单 → ./ura → 注册表）
③ 设置与浏览器能力就绪（页面清单 / https 来源 / 自动化）
④ URA 与资源同步（缓存 / 结构化数据 / 订阅）
⑤ 用户状态载入（现场 / 主题）
⑥ Agent 宿主装配（pi 运行时 + harness + 事件桥）
⑦ 视图宿主装配（WebContentsView · 交互 · 浏览器自动化）
⑧ 命令路由与原生设施
⑨ 建窗 + 菜单 + 视图恢复（懒物化）
⑩ 系统视图与首次布局
⑪ 渲染层握手（订阅 → 快照）
```

关闭顺序相反：中止流式 → 收敛写队列 → 落盘现场 → 销毁视图 → 关闭结构化数据。

## 八、持久化

| 位置       | 内容                              | 粒度   | 可重建 |
| ---------- | --------------------------------- | ------ | ------ |
| 应用数据   | 模型目录 · 凭证 · 全局设置        | 应用   | 否     |
| 工作区目录 | 工作区描述 · 工作区设置           | 工作区 | 否     |
| 会话目录   | 会话 JSONL                        | 工作区 | 否     |
| 用户状态   | 主题 / 栏宽 / 打开集合 / 助手形态 | 工作区 | 是     |
| 派生数据   | 资源地图 · 结构化索引 · 网页快照  | 工作区 | 是     |
| 插件       | 安装目录 / 本地来源声明           | 应用   | 否     |

写策略：内存 + 标脏 + 防抖 + 退出强制落盘；每次写入临时文件后原子替换。派生数据带版本，格式变化时后台重建。

## 九、信任边界

```
主进程（自家）        全量能力
插件（外部）          主进程代码，安装即授权
页面 / 网页（外部）   沙箱渲染进程，无 Node
设置页（自家）        与页面同一沙箱，只能调白名单命令
```

- 信任在安装期：插件能执行主进程代码，来源必须明示。
- 运行时靠边界：页面只能走页面数据面；凭证不出主进程；模型侧只拿 schema 与 query。
- 网页无桥；导航与窗口打开由视图宿主收起（网页链接转应用内标签，外链交系统）。

## 十、平台事实

Electron 的几个事实直接决定了页面域的结构：

| 事实                                     | 设计后果                                     |
| ---------------------------------------- | -------------------------------------------- |
| WebContentsView 是 OS 表面，DOM 无法跨越 | 壳层不能覆盖内容；模态 / 菜单 / 拖拽走原生层 |
| 视图只有「后加者在上」                   | 层级显式化：内容 → 助手 → 浮层 → 捕获层      |
| 一个 webContents 只能出现在一个视图      | 标签与浮层不能共享同一实例                   |
| 容器寿命长于页面                         | 视图命令按「容器在、页面可能已死」处理       |
| 页面进程可能崩溃或被回收                 | 视图各自进入错误 / 待重载，不影响其他视图    |
| 内容投递无回执                           | 必须等页面就绪后再投递，主进程排队           |
| 导航是后一次抢占前一次                   | 取消不是失败，只认主框架真实失败             |
| 视图 bounds 为整数 DIP                   | 全部几何在主进程按窗口坐标计算               |
| 视图整体捕获鼠标                         | 分隔条两侧必须留让位带                       |
| 协议 handler 按 session 隔离             | 每个分区都要注册页面协议                     |
| 沙箱 preload 只接受 CJS 单文件           | 契约桥单文件构建，共享常量内联               |
| 主进程 ESM 无 import map                 | 扩展隔离不能靠模块系统，信任在安装期         |

## 十一、构建与分发

| 面      | 方案                                                        |
| ------- | ----------------------------------------------------------- |
| 主进程  | ESM 单 bundle，依赖全部内联                                 |
| preload | 多入口 CJS 单文件，通道常量内联                             |
| 渲染层  | 多页面构建（工作台 / 助手 / 浮层）                          |
| 插件页  | 插件目录不打包，构建期整目录拷贝                            |
| 设置页  | 随应用构建拷贝，与插件页同协议装载                          |
| 应用包  | asar + fuses：禁运行期 Node、禁环境变量注入、只从 asar 加载 |
| 调试    | 可选调试端口；停靠式 DevTools；诊断日志落盘                 |

## 十二、关键决策

| 决策               | 理由                                       | 代价                     |
| ------------------ | ------------------------------------------ | ------------------------ |
| 复用 pi 内核       | 模型、轮次、会话与扩展生态同源             | 跟随上游演进             |
| 停用 pi 内置工具   | 业务不需要任意代码执行，能力必须经资源管道 | 自持同名工具与语义       |
| 查表分发、不做探测 | 行为确定、失败可定位                       | 新格式必须声明           |
| 结构化数据只做派生 | 查询与列表不每次拉全量                     | 需要重建与一致性策略     |
| 页面是唯一内容表面 | 一套装载 / 桥 / 白名单                     | 页面必须遵守页面基建     |
| 插件只有一种形态   | 设置与浏览器属于框架，不需要类型分类       | 框架承担设置与浏览器实现 |
| 在线网站统一三段   | 不为每个站点写 adapter                     | 特殊站点只能靠通用自动化 |
| 布局与视图归主进程 | 几何唯一来源，拖拽可跨视图                 | 主进程承担更多状态       |

## 十三、风险

| 风险             | 缓解                                          |
| ---------------- | --------------------------------------------- |
| pi 上游契约变化  | 只用官方扩展点与公开导出，升级按 CLI 行为验收 |
| 插件拥有进程权限 | 安装时明示来源；页面沙箱；设置页只读白名单    |
| 注册覆盖         | 诊断记录覆盖关系；内置实现可回退              |
| 远端写延迟       | 分片队列 + 超时标记待对账；读不进队列         |
| 原生视图错位     | 单轨布局 + 让位带 + 停靠 DevTools 视口上报    |

## 十四、验收

1. **唯一入口**：人 / AI / 页面都经 URA 访问资源；写通道唯一，队列串行、后写覆盖先写。
2. **降级与重建**：任一环失败降级 raw 并记录；删除派生数据后由来源重建，期间读直通。
3. **真相源**：重建渲染层后，打开集合、激活项、栏宽、主题与会话现场全部恢复。
4. **布局单轨**：窗口缩放、侧栏收放、助手浮动、DevTools 停靠后，壳层与原生视图边界一致。
5. **三类承载清晰**：插件可装可卸；设置页只随应用发布；浏览器无需逐站配置即可打开在线网页。
6. **安全与退出**：页面命令被白名单限制；凭证不出主进程；流式中退出不挂起、无半写文件。
