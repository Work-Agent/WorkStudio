## 一、问题与设计主张

### 1.1 问题：三类 agent 的差异

| 维度     | Personal Agent         | Coding Agent           | Work Agent（本项目）                     |
| -------- | ---------------------- | ---------------------- | ---------------------------------------- |
| 服务对象 | 个人 · 日常事务        | 开发者 · 代码库        | 岗位 · 业务工作                          |
| 资料形态 | 少来源、非结构化、云端 | 单一来源、结构化、本地 | **多来源、多格式、权限不一**             |
| 资料性质 | 文本 / 会话：容错高    | 代码：可执行、可验证   | 内容 + 数据（数据对模型只给 schema）     |
| 语境     | 个人偏好、历史对话     | 仓库结构、依赖、构建   | 业务规则、流程、权限边界                 |
| 目的     | 快速完成一次任务       | 改对代码               | 在规则内完成操作（正确 / 合规 / 可追溯） |
| 执行路线 | 检索 + 生成 + 调用工具 | 生成代码 → 执行 → 验证 | 编排确定性工具，尽量不生成代码           |
| 安全     | 个人隐私               | 项目信任 + 路径保护    | 数据不出域、脱敏、审计                   |

结论：L0 / L1 与领域无关，整体保留；**L2 是差异化所在**；应用层从 TUI 换成桌面工作台。

### 1.2 本质：碎片化

工作型 agent 的原料不是「一个代码库」或「一段对话」，而是碎片：**来源**（本地 / 云 / 业务系统 / 网页 / 邮件）、**格式**（docx / pdf / 表格 / 邮件 / 网页 / 画布）、**语境**（规则 / 流程 / 模板分散）、**权限**（身份 / 可见性 / 写入范围不同）、**时间**（版本 / 同步 / 并发）。

代价是：同一份内容在不同工具里各存一份、模型看不到数据、界面为每种格式各做一套、写回时互相覆盖。工作台的第一职责是**收敛碎片**——不是在聊天壳外面再包一层，而是把访问、解释、控制、呈现收进一条管道。

### 1.3 三条设计主张

| 主张                               | 机制                                                                                               | 它直接消除的问题                                            |
| ---------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| **一条资源管道**                   | 统一标识进入 → 来源取内容 → 格式解释 → 结构化数据 → 投影出口；人 / AI / 页面都只经这条管道         | 两套读写实现 · 格式与来源耦合 · 并发写覆盖 · 数据绕道进模型 |
| **一棵状态树、一次投影**           | 主进程持唯一状态树（含布局几何），界面只持投影；变更只有一条通道：命令 → 事务 → 版本 → 快照 / 事件 | 状态不同步 · 重建依赖缓存 · 多视图竞态 · 几何裂缝           |
| **内容表面独立、扩展只有一个体系** | 标签内容是独立 OS 表面，由 pi 的资源轴 / 注册轴提供的页面与能力组装；壳层只画 chrome               | 壳层与内容互相遮挡 · 双插件体系 · 扩展能力分裂              |

三条主张是设计的出发点，后文的结构、机制、约束都是它们的展开与推论。

### 1.4 产品形态：以文件为中心的 Studio

**文件回答「有什么」，会话回答「做了什么」，插件回答「能做什么」。**

- 文件面向**用户（消费者）**：资源管理器式的**主窗口**，浏览、打开、查看、编辑；
- 会话面向**核验**：围绕当前任务的执行过程（提示、工具调用、审批）；
- 插件面向**社区开发者**：表达这个工作台能做什么。

工作台以文件为主轴，**Studio 是主形态**；Chat 与虚拟桌面按需展开（助手常驻可收起，插件页作为面板 / 标签出现）。

### 1.5 需求对照

| 需求                  | 由哪条主张满足                                                     |
| --------------------- | ------------------------------------------------------------------ |
| R1 Pi 兼容            | 主张三：不 fork，能力只经 pi 的两条轴进入                          |
| R2 一份来源，两份投射 | 主张一：一条管道，AI 与 editor 两种出口                            |
| R3 数据边界           | 主张一：可见性策略在管道内（凭证不进渲染层，行数据不进模型上下文） |

其余要求（主题统一、事件可恢复、格式可扩展、并发可控）是主张的推论，落在机制与支撑章节，不单列为目标。

## 二、领域模型与状态归属

### 2.1 领域模型

**聚合根是工作区**：它同时是隔离边界、持久化边界与换代边界——工作区切换，其下实体整体更替。工作区之下两条主线：**文件**（人用面：导航、查看与修改）与**会话**（AI 用面：提示、资源、注册与消息）。两侧消费同一份数据：文件侧面向查看与修改，会话侧以工具调用消费同一资源。

图例：连线 = 包含关系（1:N / 1:1）；资源轴是声明（装载期读取），注册轴是运行时填充。

```
Workspace 工作区（聚合根：隔离 / 持久化 / 换代边界）
│
├─1:N─ Files 文件（人用面 · 来源：本地文档 / 业务数据 / 网站资料 / 临时网页）
│      ├─ Editor 导航（派生视图 · 可由来源重建）
│      │    ├─ 浏览目录 / 文件列表
│      │    └─ 按 glob 查找路径
│      ├─ Editor pane 编辑区（文件操作）
│      │    ├─ 查看（取内容 + 呈现）
│      │    ├─ 编辑
│      │    ├─ 保存
│      │    ├─ 检索
│      │    └─ 刷新 / 重载
│      └─ 变更订阅（内容 / 结构变更）
│
├─1:N─ Sessions 会话（AI 用面）
│      ├─ System prompt 系统提示词（角色 · 指令 · 约束）
│      ├─ Context files 上下文文件（AGENTS.md 等 · 自动发现）
│      ├─ Resources 资源轴 · 声明式（资源包清单 / 约定目录 / 设置）
│      │    ├─ Extensions 扩展（资源包）
│      │    ├─ Skills 技能（SKILL.md · 按需加载）
│      │    ├─ Prompts 提示词模板（*.md）
│      │    └─ Themes 主题（*.json）
│      ├─ Registrations 注册轴 · 命令式（扩展工厂运行时填充）
│      │    ├─ Tools 可调用工具（声明给模型）
│      │    ├─ Commands 命令（slash 命令）
│      │    ├─ Shortcuts 快捷键（自定义按键）
│      │    ├─ Flags 标志（feature flags）
│      │    ├─ Handlers 事件钩子
│      │    ├─ Renderers 渲染器（message · entry · markdown）
│      │    └─ Providers 供应商（MCP · 虚拟模型）
│      └─ Messages 消息 · 1:N
│           └─ Tool calls 工具调用（call 实例 · 引用 Tools 定义）
│
└─1:1─ Workspace scene 工作区现场（偏好与现场 · 可丢弃 · 重建为默认现场）

横向扩展能力（作用于以上全部业务数据）
├─ WorkStudio 插件：页面 · 资源实现 · 技能 / 提示 / 主题
└─ Pi 扩展（Extension）：工具 · 命令 · 钩子 · 供应商
```

WorkStudio 插件与 Pi 扩展是横向扩展能力，作用于以上全部业务数据（机制见 §4.4）。

**实体表**

| 实体            | 标识                | 真相源                | 持久化          |
| --------------- | ------------------- | --------------------- | --------------- |
| 工作区          | 路径                | 工作区注册            | 自描述文件      |
| 分组            | 来源 + 域           | 资源来源              | 派生            |
| 文件            | 来源 + 路径         | 来源（磁盘 / 服务器） | 来源侧 + 派生层 |
| 会话            | 会话文件            | pi 会话管理器         | 会话文件        |
| 消息 · 工具调用 | 会话内序号          | pi 会话管理器         | 会话文件        |
| WorkStudio 插件 | 插件 id             | 插件注册表            | 插件根          |
| Pi 扩展         | 扩展 id             | pi 装载               | 插件根          |
| 模型与配置      | provider / model id | pi 设置与凭证链       | 设置文件        |
| 技能 · 命令     | 名称                | pi 资源装载           | 插件根 / 内置   |
| 工作区现场      | 工作区              | 用户状态服务          | 用户状态文件    |

### 2.2 三个视角：文件 / 会话 / 插件

产品以文件为中心，**Studio** 是主形态；另两面是它的过程面与能力面。三者同处一个窗口。

| 视角     | 表达         | 形态                                 | 受众           | 核心对象               | 状态归属                                  | 谁扩展                                   |
| -------- | ------------ | ------------------------------------ | -------------- | ---------------------- | ----------------------------------------- | ---------------------------------------- |
| **文件** | **有什么**   | **Studio**：资源管理器 + 查看 / 编辑 | 用户（消费者） | 文件 · 分组 · 页面     | `domain.files` · `ui.viewCollection`      | 插件提供页面与格式实现                   |
| **会话** | **做了什么** | **Chat**：执行过程与干预             | 用户（核验）   | 会话 · 消息 · 工具调用 | `external.piSessions` · `domain.sessions` | Pi 扩展注册工具 / 命令 / 钩子            |
| **插件** | **能做什么** | **虚拟桌面**：插件页组成的能力面     | 社区开发者     | 插件 · 贡献点          | `external.pluginRegistry`                 | 插件本身（可携带 Plugin / Pi Extension） |

**三者的关系**：

- **文件**回答「有什么」：内容面，决定资源怎么被打开、解释与呈现；
- **会话**回答「做了什么」：过程面，记录并允许核验在规则内怎么操作这些资源；
- **插件**回答「能做什么」：能力面，决定前两者可用的格式、页面与工具从哪来。

三者在状态树上分别落在 `domain`（文件与现场）、`external.piSessions`（会话本体在 pi）、`external.pluginRegistry`（插件清单），通过命令与页面会话连接——不互相持有对方的实体。

**失败视角也不同**：文件侧失败是「打不开 / 渲染不了」（raw 兜底、键失效清理）；会话侧失败是「模型或工具失败」（错误进消息流、会话回空闲）；插件侧失败是「能力不可用」（加载诊断、注册被拒）。

## 三、整体架构

一句话：**main 内部分层，扩展横向注册**。URA 的三段（来源 / 格式 / 出口）就是 main 的内部分层；三类 registry + 插件注册就是横向扩展机制。

### 3.1 纵向：main 的内部分层与通讯

```
┌─ views（渲染进程） ──────────────────────────────────────────────────────────────────────────┐
│ 壳层 DOM：标题栏 · 侧栏 · 标签栏 · 空态                                                      │
│ Chat 助手页 │ 内容页面 ×N（页面内 render）│ 网页 ×N │ 浮层 / 捕获层                          │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
        ▼ preload 契约桥：白名单 API · 无 Node · 无裸 IPC
        ▼ IPC：命令 ▼ ｜ 事件 / 状态 / 视图快照 ▲ ｜ 页面会话（WebContents 消息）
┌─ main（Electron 主进程） ────────────────────────────────────────────────────────────────────┐
│ 装配层：生命周期 · 窗口 · 协议注册 · IPC handler · 域服务装配 · 菜单 · 退出                  │
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│ 域服务层：AgentSession 宿主 · 视图宿主 · 命令路由 · 事件桥 · 交互控制器                      │
│           状态树：workspace · sessions/<id> · derived · external                             │
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│ harness：提示（AGENTS.md / 资源地图 来自 URA）· 技能 · 工具                                  │
│   工具：资源管理型 7 个（URA 门面）· 操作型（浏览器族等 · 契约注入）                         │
│   URA：门面 → 来源（transport）→ 格式（codec）→ 投影（consumer）                             │
│        投影：agent 文本 ｜ editor 页面入口 + 数据（render 在 views）                         │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
        ▲ 官方扩展点：资源装载 · 扩展运行器
┌─ pi SDK ─────────────────────────────────────────────────────────────────────────────────────┐
│ L0 模型 API · L1 轮次循环 · 会话与持久化 · 资源装载 · 扩展运行器                             │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **三层进程边界**：views（渲染进程）· main（主进程）· pi SDK；
- **main 内部分三层**：装配层（组合根）→ 域服务层（AgentSession 宿主 / 路由 / 状态 / 视图）→ harness（提示 / 技能 / 工具 / URA）；
- **会话是域服务的基本单位**：一个 AgentSession = 领域模型中的一个会话，携带自己的上下文（AGENTS.md / 资源地图）与工具集；
- **URA 内部再分层**：门面 → 来源（transport）→ 格式（codec）→ 投影（consumer）；
- **render 在 views**：consumer 只在 main 产出「文本投影」或「页面入口 + 数据」，页面内的 render 在渲染进程；
- **工具分两类**：资源管理型（read / write / edit / grep / find / ls / query）经 URA；操作型（浏览器族等）经契约注入；
- **上下文同源**：AGENTS.md 与资源地图也来自 URA（发现 → 读取 → agent 投影），不旁路读文件；
- **两层边界**：preload 契约桥（views → IPC）与官方扩展点（main → pi）；
- **IPC**：命令下行、事件 / 状态 / 视图快照上行、页面会话双向（WebContents 消息）；
- **扩展不是一层**：WorkStudio 插件与 Pi 扩展由 pi 装载、注册进 agent，代码运行在 main（机制见 §4.4）。

### 3.2 横向：扩展机制（注册表 + 插件）

```
门面              来源              格式              数据              出口（main 投影）
read / write      transport         codec             store             consumer
edit / grep       磁盘 · HTTP       docx · pdf        结构化查询        AI 文本 / 页面入口 + 数据
find / ls         WebDAV · JMAP     表格 · 邮件       版本戳            → 页面内 render（views）
query / watch
│                 ▲                 ▲                 ▲                 ▲
│                 插件实现来源      插件实现格式      插件实现存储      插件实现页面
└──────────────────── 写：写会话 · 分片队列 · 版本校验 · 冲突出口 ─────────────┘
```

三类实现各有一个注册表：**来源注册表**（按协议）· **格式注册表**（按内容类型 × 格式提示）· **出口注册表**（按文档类型 × agent / editor）。插件注册实现，用户配置可覆盖。

- **门面统一**：人（Studio 操作）与 AI 的 7 个资源管理型工具走同一个门面，不绑定实现；
- **render 在 views**：consumer 只产出文本或页面入口 + 数据，渲染发生在渲染进程的页面里；
- **每段可扩展**：来源 / 格式 / 数据 / 出口四段都由插件实现，新增格式或来源只写一段；
- **写只有一条**：草稿 → 提交 → 分片队列 → 版本校验 → 冲突出口；
- **读只查表**：来源 → 格式提示 → 文档类型 → 出口，任一环失败降级 raw。

## 四、核心模块

### 4.1 Harness 与资源管道（URA）

harness 是自持能力层：提示、技能、两类工具，外加 **URA（资源访问部分）**。**AGENTS.md 由 URA 生成并维护**（每工作区一份的资源地图），智能体侧按版本从 URA 注入，不旁路读文件。

| 工具类别   | 内容                                                   | 通道                   |
| ---------- | ------------------------------------------------------ | ---------------------- |
| 资源管理型 | read · write · edit · grep · find · ls · query         | URA 门面               |
| 操作型     | 浏览器族（打开 / 导航 / 读取 / 点击 / 截图）· 业务动作 | 各自契约注入，不经 URA |

URA 是资源内容的唯一入口：门面 → 来源 → 格式 → 数据 → 出口（出口只产出文本投影或页面入口 + 数据，render 在 views）。

| 控制项   | 机制                                                           |
| -------- | -------------------------------------------------------------- |
| 物理访问 | 只有来源实现触达文件 / 网络 / 服务；管道按协议路由到已注册实现 |
| 可见性   | 模型侧只给 schema；页面侧按可编辑投影提供                      |
| 并发     | 写会话 + 分片队列 + 版本校验                                   |
| 传播     | 所有写经同一管线 → 解析缓存 / 结构化数据 / 订阅一致            |
| 审计     | 读 / 写 / 降级记录来源、调用方、链路                           |

**注册接口**（插件通过 package.json 暴露，见 §4.4 与 [`agent-design.md`](./agent-design.md) §2.3）：

| 接口 | 注册什么 | 谁实现 |
| --- | --- | --- |
| `registerTransport` | 来源：协议 → 内容 + 格式提示 + 版本 | 插件 |
| `registerCodec` | 格式：内容类型 × 提示 → 结构化文档 + 文档类型 | 插件 |
| `registerStore` | 数据：文档类型 → 结构化查询 | 插件 |
| `registerConsumer` | 投影：文档类型 × agent / editor → 文本 / 页面入口 + 数据 | 插件 |
| `registerCollection` | 集合：侧栏分组（分组 → 资源条目 + 图标） | 插件 |
| `registerViewAction` | 动作：地址栏工具条（目标视图 → 按钮 + 开关状态） | 插件 |

内置来源：`file`（读写）与 `http(s)`（只读、共享浏览器 session、能力 `read/live`）。html 的 editor 出口按 transport 能力选择：具备 `live` 时用实时浏览器视图，否则用页面渲染器。

两侧消费同一门面：

| 用户侧操作  | 细粒度操作                        | AI 侧（工具）  |
| ----------- | --------------------------------- | -------------- |
| 浏览 / 查找 | ls · find                         | 同左           |
| 查看        | read + render                     | read           |
| 编辑        | 写会话（stage / apply）           | 无草稿（直写） |
| 保存        | 提交（commit）· 单步 edit / write | edit · write   |
| 检索        | grep                              | grep · query   |
| 外部变更    | watch                             | watch          |

写：草稿不落盘、提交才写入；同键串行；过期写按基线拒绝并返回三份内容；冲突由发起方选择重放 / 弃稿 / 覆盖。
读：查表分发（来源 → 格式 → 文档类型 → 出口），不做探测；任一环失败降级 raw 并记录降级点。

### 4.2 状态树与现场

**聚合根是 workspace**：状态树就是这棵聚合树，聚合之外只有两个分区（派生与外部引用）。

```
聚合内：workspace 子树（根 = 聚合根）
└─ workspace（当前工作区 · 聚合根）
    ├─ files / groups          持久态：来源为真值，索引可重建
    ├─ sessions/<id>           会话级 · 相互隔离
    │    ├─ context            AGENTS.md 投影 · 资源地图 · 技能选中集
    │    ├─ tools              工具集：资源管理型 + 操作型
    │    ├─ messages           引用 pi + 游标
    │    └─ runtime            流式 · 队列 · 档位
    ├─ scene                   持久态：偏好 · 打开集合键 · 布局几何
    └─ ui                      viewCollection · sidebar / layout · overlays / interaction（交互态细化见 views-design）

聚合外：同一棵树上的派生与引用分区
├─ derived                     派生态：resourceMap · structuredData · pageCache
└─ external                    外部态：piSessions · resourceContents · pluginRegistry
```

| 类别   | 状态                                                 | 策略                 |
| ------ | ---------------------------------------------------- | -------------------- |
| 持久态 | scene · viewCollection · sidebar / layout · 会话现场 | 标脏 + 防抖 + 原子写 |
| 派生态 | 资源地图 · AGENTS.md 投影 · 结构化数据 · 页面缓存    | 选择器计算，可重建   |
| 瞬态   | overlays · interaction · 流式 · 队列                 | 只存内存，不落盘     |
| 外部态 | pi 会话与消息 · 资源内容 · 插件清单                  | 引用 + 游标，不复制  |

1. **聚合换代**：工作区切换 = workspace 子树整体替换；derived 清空重建，external 重绑。
2. **会话隔离**：workspace.sessions/<id> 互不引用；会话换代 = 该子树替换（上下文、工具、消息、运行时）。
3. **上下文是投影**：AGENTS.md / 资源地图 / 工具集是会话子树的投影，来自 URA 与 pi 的装载，不旁路读文件。
4. **IPC 以会话为边界**：会话域命令解析到目标 session 子树，跨会话访问被拒；文件域命令是工作区级。
5. **一条通道 + 单调版本**：命令 → 事务（跨切片原子）→ 版本 → 快照 / 事件。

### 4.3 视图与页面

| 表面        | 承载                                          | 生命周期             |
| ----------- | --------------------------------------------- | -------------------- |
| 工作台壳层  | 标题栏 / 侧栏 / 标签栏 / 空态 / 分隔条（DOM） | 主窗口               |
| Chat 助手页 | 会话标签、消息流、输入区                      | 系统视图（单例）     |
| 内容页面 ×N | 渲染器、编辑器、插件页（每插件独立分区）      | 标签集合             |
| 网页 ×N     | 外部站点（raw 渲染）                          | 标签集合             |
| 浮层        | 模态、扩展 UI 对话框                          | 系统视图（单例）     |
| 指针捕获层  | 交互期间的指针事件入口                        | 系统视图（常驻预热） |

- **视图宿主独占**：创建 / 几何 / 层级 / 生命周期 / 指针归主进程；页面只声明入口。
- **布局单轨**：几何只有一个来源，壳层 DOM 与原生视图消费同一份矩形。
- **页面会话**：打开 → 就绪 → 投递 → 脏态 / 提交 → 释放；页面只持有白名单桥。

views 只消费 agent 的契约：

| 契约面   | views 得到什么                   | views 不碰                     |
| -------- | -------------------------------- | ------------------------------ |
| 页面解析 | 用哪个页面、入口地址、声明动作   | 格式识别、编解码、来源访问     |
| 页面会话 | 投递、外部变更、提交、冲突、释放 | 版本 token、写队列、结构化数据 |
| 变更订阅 | 资源与列表的变更                 | 监听实现、同步策略             |
| 命令     | 资源 / 工作区 / 会话等语义命令   | 直接读写文件或网络             |

### 4.4 插件与扩展

| 扩展                     | 提供什么                                                            | 归属                                  |
| ------------------------ | ------------------------------------------------------------------- | ------------------------------------- |
| **WorkStudio 插件**      | 页面（渲染器 / 编辑器 / 插件页）· 资源访问实现 | WorkStudio 管理（清单 / 安装 / 信任） |
| **Pi 扩展（Extension）** | 工具 · 命令 · 钩子 · 供应商                                         | pi 装载并在注册轴注册                 |

- 一个 WorkStudio 插件可携带 0..N 个 Plugin 和 Pi Extension。
- **插件就是 npm 包**：`exports["./ura"]` 指向注册入口（加载时调用 `registerXXX`）；`workstudio` 字段声明 `page`（渲染器页）与 `settings`（插件自己的设置页，可选）、`icon`（语义名或 favicon 文件）；pi 扩展与技能单独管理。设置面板（偏好设置等）不在此列，属主进程设置能力。页面资源默认只允许各自目录，`webAccessible` 仅用于覆盖。不再有单独的 manifest.json。
- **一个插件最多两个页面**：`workstudio.page`（渲染器页）+ `workstudio.settings`（设置页，可选）；editor consumer 直接用 page，不单独注册页面。
- **插件**：自带 webapp + transport/codec/projection，是 `src/plugins` 下的 `package.json` 包；设置页与浏览器能力（视图 / 来源 / 投影 / 工具 / 注入）是主进程能力，不是插件。
- **一次装配**：插件与扩展在启动时注册进 agent，运行期不再装载。
- **信任在安装期**：扩展跑主进程、拥有进程权限（安装即授权、来源明示）；页面跑沙箱（无 Node、只调白名单命令）。
- **工具面不外包**：工具只由 harness 注册；插件不能注册工具、不能创建视图。
- **集合是投影不是 UI**：插件贡献分组数据（`registerCollection`），侧栏渲染与排序归壳层。

应用启动

## 五、通讯规范

### 5.1 通道语义

契约桥按用途分组，每组只有一个通道；通道名与载荷类型是实现细节，不在本设计内约束，语义如下：

| 用途           | 方向                 | 语义                                                                   |
| -------------- | -------------------- | ---------------------------------------------------------------------- |
| **命令**       | 渲染 → 主进程        | 唯一写路径：`域.动作` + 结构化信封，返回 `ok/data` 或 `ok:false/error` |
| **握手**       | 渲染 → 主进程        | 启动 / 重连：Agent 快照 + 事件游标 + 壳层快照 + 视图集合 + 插件清单    |
| **事件**       | 主进程 → 渲染        | 会话与应用事件帧（带单调序号）                                         |
| **状态**       | 主进程 → 渲染        | 壳层快照（用户状态 + 布局 + 浮动几何 + 拖拽预览）                      |
| **视图**       | 主进程 → 渲染        | 视图集合快照（顺序即标签顺序，含激活位）                               |
| **资源**       | 主进程 → 渲染        | 资源变更（条目 / 分组 / 每轮收敛）                                     |
| **视图总线**   | 双向（经主进程中转） | 内容投递、就绪握手、脏态、提交、动作与动作状态回报、主题               |
| **交互**       | 渲染 → 主进程        | 影响几何的拖拽会话：开始 / 移动信号 / 结束 / 取消（含预览回流）        |
| **扩展 UI**    | 双向                 | pi 扩展的对话框与通知（请求 + 应答）                                   |
| **页面数据面** | 页面 → 主进程        | 白名单命令，转发到同一命令目录                                         |
| **原生能力**   | 渲染 → 主进程        | 打开路径 / 打开外部链接 / 目录选择 / 原生菜单弹出（+ 选择回执）        |
| **捕获层信号** | 捕获层 → 主进程      | 交互期间的指针事件（只发信号，不暴露 API）                             |

### 5.2 命令契约

- 命令名 = `域.动作`；域划分与目录见 [`agent-design.md`](./agent-design.md) §七（业务域）与 [`views-design.md`](./views-design.md) §五（视图域）。
- 响应只有两种结果：成功带数据，或失败带错误码与消息；校验与错误在域内完成。
- **幂等**：同一命令重复调用收敛为 no-op 或等价结果（如打开同键视图 = 激活而非新增）。
- **发送方校验**：每个通道声明允许的来源；页面只能走页面数据面，且只能触达白名单命令。
- **会话为边界**：会话域命令解析到目标会话子树，跨会话访问被拒；文件域命令属工作区级。
- 渲染层只消费成功数据；错误统一进壳层提示（行内错误由发起页面承担）。

### 5.3 握手与恢复

- 握手是渲染层的**唯一初始化入口**：先订阅事件 / 状态 / 视图，再取快照，然后用快照覆盖本地投影——订阅先于快照保证无丢帧。
- 快照内容：Agent 状态（模型 / 档位 / 流式中 / 会话路径 / 队列计数）、事件游标、壳层快照、打开集合全量、插件清单。
- 原生系统视图（助手 / 浮层）可各自握手；工作台重载不重建视图实例（实例寿命与渲染层进程解耦）。

### 5.4 事件帧、定序与合帧

- 事件帧 = 单调递增序号 + 事件体；pi 会话事件与应用内部事件**共用同一序列**。
- **合帧**：高频流式增量（消息更新、工具执行更新、bash 执行更新）在 16ms 窗口内只保留最新帧；定序事件（消息起止、工具起止、轮次结束、队列与档位变更、应用事件）不合并。合帧帧沿用原序号槽位，保持定序稳定。
- **缺口恢复**：渲染层按序号连续性检测缺口 → 重新握手 → 用快照重建投影；**不做增量回放**（重建比补齐更简单且必然正确）。

### 5.5 交互通道

- 交互是**主进程拥有的会话**：渲染层只上报移动信号与锚点，主进程以屏幕光标为权威坐标计算预览、应用预览 bounds、广播；结束时夹取并提交（栏宽 / 侧栏收起 / 浮动几何）。
- 会话只在指针按下时建立；任一结束信号（发起方抬起 / 捕获层抬起 / 窗口失焦 / `Esc`）销毁会话，重复结束为 no-op。
- 交互期由常驻捕获层接收指针事件（原生视图恒在 DOM 之上，指针会离开发起者矩形）。

### 5.6 页面数据面与页面桥

- 页面只持有注入的桥对象：白名单命令调用 + 视图总线；无 Node、无裸 IPC。
- 主进程先校验来源属于页面视图，再按映射转发到**同一条命令实现**（同一校验、同一错误码）；未列入映射的命令一律不存在。
- 页面不可触达视图域命令与用户状态写命令：设置类页面需要的能力（会话 / 工作区 / 存储 / 资源）按白名单放行。
- 页面桥语义：主进程 → 页面（投递内容 / 外部变更 / 触发保存 / 主题）；页面 → 主进程（就绪 / 脏态 / 提交 / 动作回报 / 请求差异）。页面只声明入口与协议，不持有视图句柄。

## 六、平台事实与约束（Electron）

| 平台事实                                                       | 对设计的约束                                                                   |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 窗口内独立视图是 OS 表面，DOM 的层级无法跨越它                 | 壳层 DOM 不能覆盖内容面；模态、菜单、拖拽必须走原生层                          |
| 视图之间只有「后加者置顶」一种层级手段                         | 层级策略显式化并集中管理，不允许靠 DOM 顺序解决遮挡                            |
| 一个 webContents 同时只能出现在一个视图内                      | 同一页面不能既在标签又在浮层；共享实例或分别加载二选一                         |
| 视图容器与页面的寿命不同步：页面销毁后容器仍可改几何、摘挂     | 全部视图命令与异步回调按「容器在、页面可能已死」写守卫；页面死后除判活外不触碰 |
| 一个渲染进程可承载多个页面，且可被系统回收；平台不暴露进程对象 | 崩溃 / 内存回收只能由页面级事后事件推导；受影响视图各自收敛，不牵动其他视图    |
| 内容投递是「发后不管」：无回执、无排队、失败无提示             | 投递必须在页面明确就绪后进行；未就绪一律自行排队                               |
| 导航是「后一次抢占前一次」，被抢占以取消事件收场               | 取消不是失败；状态机只认主框架的真实失败                                       |
| 键盘事件只在有焦点的页面上派发                                 | 快捷键必须在主进程挂到全部页面后统一路由，不能依赖单一页面监听                 |
| 视图 bounds 为整数 DIP，以窗口内容坐标为基准                   | 布局计算全部在窗口内坐标；全局屏幕坐标只在交互层换算                           |
| 视图矩形整体捕获鼠标，无逐像素穿透                             | 分隔条必须让位（两侧各留让位带），否则把手不可点                               |
| 视图内容被裁剪在自身矩形内                                     | 视图内的弹出层（模型 / 技能选择器）必须在视图内展开                            |
| 会话级能力（协议 handler、权限、缓存）按分区隔离               | 自定义协议必须逐分区注册；漏注册表现为加载失败                                 |
| 停靠的开发者工具画在窗口 DOM 之上                              | 渲染层上报页面视口，布局以「窗口与视口的较小者」计算，让原生视图整体让位       |
| 分离式开发者工具窗口不暴露给应用 API                           | 只有停靠式切换；不自持调试窗口                                                 |
| 沙箱 preload 只接受 CJS、单文件、无相对 require                | 契约桥必须单文件构建，共享常量内联                                             |
| 打包期 fuses 禁用运行期 Node 与 asar 外加载                    | 全部依赖打进主进程 bundle；不使用动态加载                                      |
| 主进程 ESM 没有 import map，动态加载不可完全拦截               | 扩展隔离不能靠模块系统；信任在安装期（扩展拥有进程权限），页面仍沙箱隔离       |
| 窗口控制覆盖层（WCO）几何由平台绘制、位置因平台而异            | 不写死留白；按平台判定 + 运行时实测反推                                        |
| 系统主题是原生控件外观的真相                                   | 主题变更时同步窗口底色、原生视图底色、覆盖层配色与全部页面                     |

## 七、生命周期

### 7.1 启动（阶段与顺序保证）

| 阶段                     | 内容                                                   | 顺序保证                                      |
| ------------------------ | ------------------------------------------------------ | --------------------------------------------- |
| ① 工作区解析             | 注册表为空则创建默认工作区；当前 = 最近打开            | 一切按工作区隔离的数据在此之前不能载入        |
| ② 扩展装载与注册         | 资源轴装载 → 扩展工厂执行 → 注册校验 → 分发表          | 先于一切消费方（资源管道与 Agent 宿主都查表） |
| ③ 资源管道与同步         | 来源注册 → 解析缓存 → 结构化数据打开 / 预热 → 变更订阅 | 先于 Agent 宿主（提示中的资源地图依赖投影）   |
| ④ 用户状态载入           | 每工作区用户状态 + 系统主题同步                        | 先于视图恢复与窗口显示                        |
| ⑤ Agent 宿主装配         | pi 运行时 + harness + 事件桥 + 扩展 UI 上下文          | 先于视图宿主（内容投递依赖会话与资源就绪）    |
| ⑥ 视图宿主装配           | 视图宿主 + 交互控制器 + 浏览器自动化实现               | 先于建窗                                      |
| ⑦ 命令路由与原生设施注册 | 全部通道 handler                                       | 先于建窗（渲染层调用绝不早于 handler）        |
| ⑧ 建窗与菜单             | 主窗口 + 视图挂载 + 应用菜单                           | —                                             |
| ⑨ 视图恢复               | 按用户状态重建打开集合（全部未物化）                   | 只建记录；原生视图在首次激活时物化            |
| ⑩ 系统视图与布局         | 助手 / 浮层 / 捕获层就位，应用一次布局                 | 全部 bounds 一次落位，避免闪烁                |
| ⑪ 渲染层握手             | 先订阅后快照，重建投影                                 | 订阅先于快照                                  |

**注册失败策略**：扩展执行失败或注册校验不兼容 → 该扩展不进入运行时并记录诊断，不阻塞其余扩展；内置包失败视为构建错误，直接中止启动。

### 7.2 关闭

```
退出请求
 1. Agent 宿主销毁：中止流式执行 → 冲刷会话域 → 销毁运行时
 2. 写队列收敛：提交在途项（有超时上限）→ 标记待对账
 3. 用户状态强制落盘（防抖窗口内的最后一次写）
 4. 视图全部解绑 → 摘除 → 页面销毁（含捕获层）
 5. 结构化数据关闭（落盘校验）→ 退出
```

规则：退出路径不得有挂起（模型调用中止、队列收敛、状态 flush、视图销毁齐全）。

### 7.3 崩溃与重建

| 事件                  | 处理                                                                         |
| --------------------- | ---------------------------------------------------------------------------- |
| 工作台壳层重载 / 崩溃 | 视图实例与集合保持；渲染层重新握手恢复投影；bounds 不变（布局在主进程）      |
| 页面渲染进程崩溃      | 视图进入错误态；内存回收导致的退出只标记待重载（激活时补一次加载）           |
| 助手页崩溃            | 视图重建 + 重放会话快照（消息从会话读取，不依赖渲染层缓存）                  |
| 结构化数据损坏        | 标记待重建 → 由来源全量重扫恢复；期间读走直通（解码即用），不返回空          |
| 主进程崩溃            | 不承诺恢复；已落盘数据（会话、用户状态、配置、结构化数据）保证一致（原子写） |

## 八、持久化布局

### 8.1 数据家族

| 位置                                     | 内容                                       | 隔离粒度    | 可重建性                 |
| ---------------------------------------- | ------------------------------------------ | ----------- | ------------------------ |
| 应用数据目录                             | 模型目录 · 凭证 · 全局设置                 | 应用        | 否（用户资产）           |
| 应用数据目录 / 每工作区                  | 工作区自描述（路径 / 创建时间 / 最近打开） | 工作区      | 否                       |
| 应用数据目录 / 每工作区                  | 工作区层设置                               | 工作区      | 否                       |
| 会话目录（可配置，默认在每工作区目录内） | 会话 JSONL                                 | 工作区      | 否                       |
| 每工作区用户状态                         | 主题 / 栏宽 / 打开集合键 / 会话现场        | 工作区      | 是（丢弃后回到默认现场） |
| 每工作区结构化数据                       | 文档类型索引 / 全文索引 / 同步游标         | 工作区      | 是（由来源重建）         |
| 每工作区资源派生目录                     | 资源地图、网页快照等派生数据               | 工作区      | 是（由来源重建）         |
| 插件根                                   | 插件模块、页面资源、图标、清单             | 应用 / 用户 | 否（安装产物）           |
| 诊断日志                                 | 启动链、装配仲裁、分发轨迹与异常记录       | 应用        | 是                       |

### 8.2 写策略与迁移

- **写策略**：内存态 + 标脏 + 防抖批量 + 退出强制落盘；每次写入都是「临时文件 → 原子替换」，不存在半写文件。
- **版本迁移**：用户状态文件带版本号；载入时逐字段回落默认值（容忍向前版本），未知字段丢弃，非法值归一化。
- **派生层迁移**：结构化数据的 schema / 格式版本变化 → 标脏 → 后台重建，不做原地复杂迁移。
- **领域数据不让渲染层代写**：渲染层只能经命令影响主进程状态，不直接触碰文件。

## 九、安全基线

### 9.1 信任域与能力面

| 信任域                      | 进程                       | 能力面                                                         |
| --------------------------- | -------------------------- | -------------------------------------------------------------- |
| 主进程（自家）              | browser process            | 全量：文件、网络、原生能力、pi runtime                         |
| 扩展（外部代码）            | 主进程（pi 扩展）          | 与进程同权限：工具 / 命令 / 格式 / 投影 / 页面入口；安装时明示 |
| 工作台壳层 / 助手页（自家） | 渲染进程                   | 白名单契约桥（不暴露裸 IPC、不暴露 Node）                      |
| 页面（外部代码）            | 渲染进程（每插件独立分区） | 页面数据面白名单命令 + 视图总线                                |
| 网页（任意站点）            | 渲染进程（独立分区）       | 无桥；导航与窗口打开受策略约束                                 |
| 浮层 / 捕获层（自家）       | 渲染进程                   | 仅对话框应答 / 仅指针信号                                      |

### 9.2 约定

| 面         | 约定                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 视图配置   | 全部表面：上下文隔离开 · 沙箱开 · 无 Node 集成                                                        |
| 契约桥     | 每类表面一份，只暴露语义化 API，不暴露底层通信对象                                                    |
| 会话隔离   | 页面按插件分区；网页、助手、浮层、捕获层各自独立分区                                                  |
| 窗口打开   | 一律拒绝新建窗口：网页链接转为应用内新标签，邮件 / 电话交系统，其余拒绝                               |
| 导航       | 壳层与助手阻止任意导航；页面仅允许应用协议；网页允许 http(s) 且经白名单                               |
| 内容加载   | 页面经自定义协议装载（安全 scheme，逐分区注册），生产环境不从本地文件直开                             |
| 资源白名单 | 页面只能装载插件声明的可访问资源，其余路径一律拒绝                                                    |
| CSP        | 生产环境对工作台页面注入自身来源策略；页面自持 CSP                                                    |
| 凭证       | 凭证值永不经 IPC 回传；模型目录视图剥除密钥；写盘前经 pi 加载链校验                                   |
| 数据轨     | 模型侧只暴露 schema 与 query；行数据可进页面（展示 / 编辑），不进模型上下文；写入受来源能力与权限约束 |

## 十、构建与分发

| 面       | 技术选型与约束                                                                     |
| -------- | ---------------------------------------------------------------------------------- |
| 主进程   | ESM 单 bundle，依赖全部内联——打包后不依赖运行时 node_modules 布局                  |
| 契约桥   | 多入口 CJS 单文件（沙箱与 asar 下 require 受限），共享常量内联                     |
| 视图面   | 多页面构建；捕获层用内联数据页（无独立入口）                                       |
| 插件     | 插件目录不参与打包，构建期整目录拷贝到产物目录（与生产扫描根一致）                 |
| 插件装载 | 插件目录随构建拷贝，按清单扫描安装；插件携带的 Pi 扩展入口交给 pi 装载链           |
| 应用包   | asar 打包 + fuses（禁运行期 Node / 禁环境变量注入 / 仅从 asar 加载 / 完整性校验）  |
| 开发调试 | 可选调试端口开放给自动化；菜单提供停靠式开发者工具与「重载当前视图」；诊断日志落盘 |

## 十一、关键设计决策与理由

| 决策                                           | 理由                                                               | 代价                                               |
| ---------------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 复用 pi 内核而非自建 agent 循环                | 模型适配、轮次语义、扩展生态与 CLI 同源，避免长期分叉              | 受上游 API 演进影响，需以扩展点而非改源码接缝      |
| 停用 pi 内置工具（read / bash / edit / write） | 业务场景不需要任意代码执行；能力必须经资源管道与规则约束           | 需自持同名工具并保证语义等价（资源地址、编辑契约） |
| 资源管道查表分发（不做探测）                   | 确定性优先：失败可定位、行为不随时序变化                           | 新增格式必须提供声明，无法「猜」出来               |
| 结构化数据作为工具依据                         | 远端资源不可能每次查询拉全量；查询与投影需要同一份结构             | 多一份派生存储，需要重建与一致性策略               |
| 页面即消费者（渲染器 / 编辑器 / 设置页同构）   | 一套装载、一套桥、一套白名单，界面与资源面不再各建一套             | 页面必须遵守统一桥协议，不能自带通信               |
| 两个出口异质                                   | AI 是函数式工具调用，界面是长会话与页面；强行统一会让两边都退化    | 需要维护两套形态，但共享管道与语义                 |
| 交互会话归主进程                               | 拖拽期间指针会离开原渲染进程，只有主进程能观测全局坐标             | 需要常驻捕获层与「只上报信号」的协议               |
| 设置面由主进程设置能力统一承载                 | 清单与页面同源，新增设置只加一页；插件不参与设置面                 | 设置页无法使用壳层组件，需自绘并遵守页面基建       |
| 用户状态按工作区隔离、工作区自描述             | 工作区是业务边界；「当前工作区」由最近打开派生，无第二份待同步状态 | 切换工作区是原子换代（重建运行时与各域绑定）       |

## 十二、风险与缓解

| 风险               | 影响                | 缓解                                                                              |
| ------------------ | ------------------- | --------------------------------------------------------------------------------- |
| 上游 pi 契约变化   | 装配链失效          | 只用官方扩展点与公开导出；升级以对照 CLI 行为的验收清单把关                       |
| 扩展拥有进程权限   | 安全事件            | 安装前明示来源与权限；高危包需显式确认；页面沙箱 + 白名单                         |
| 同键注册覆盖       | 行为被后装包改写    | 诊断记录覆盖关系；用户配置可禁用包 / 指定实现；内置包最后可回退                   |
| 结构化数据重建成本 | 启动慢 / 查询空窗   | 惰性重建 + 直通读兜底 + 后台全量重扫；按文档类型分片                              |
| 远端写高延迟       | 队列阻塞            | 分片队列超时释放、标记待对账；读路径不进队列                                      |
| 格式实现质量参差   | 投影失真 / 写坏内容 | raw 兜底永不失效；投影质量门槛与契约测试；写操作按版本与锚点校验                  |
| 原生视图与壳层错位 | 视觉缝隙、点击落空  | 单轨布局 + 让位带规则 + 验收项固定（窗口 / 侧栏 / 面板 / 调试器四种变化下仍一致） |
| 停靠调试器让位     | 视图与页面错位      | 渲染层上报视口，布局取较小者；不使用自持调试窗口                                  |

## 十三、验收要点

**一、URA（资源控制面）**

1. **唯一入口**：人 / AI / 页面都无法绕过门面访问资源；写通道唯一（AI 写与页面提交共享同一分片队列与版本校验）。
2. **降级与重建**：任一环缺失或失败都降级 raw 并记录降级点，不出现静默空白页；删除结构化数据后由来源重建，期间读走直通不返回空。
3. **零框架改动**：只写编码与投影即可新增格式；只写来源访问即可新增来源；AI 工具列表保持不变。
4. **数据轨**：AI 侧读数据资源只返回 schema（页面不在此限，拿到可编辑投影）；行数据不进模型上下文；shell 类工具不存在。

**二、主进程现场**

5. **真相源**：杀掉壳层渲染层后重新握手能恢复全部可见状态（打开集合、激活项、栏宽、主题、会话现场），不需要任何渲染层本地缓存。
6. **布局单轨**：窗口缩放、侧栏收起 / 展开、助手停靠 / 浮动、开发者工具停靠切换后，壳层与原生视图边界仍一致，无缝隙、无重叠。
7. **事件定序**：人为丢弃一帧后，渲染层检测缺口并全量重建，不出现消息错位或永久加载态。
8. **幂等**：同键打开不新增标签；重复关闭为 no-op；视图已销毁时命令 no-op。

**三、多视图与边界**

9. **内容与壳层分离**：资源面板内容区不存在 DOM 承载的标签内容；模态、菜单、拖拽一律走原生层。
10. **单一管理者**：页面无法创建视图或注册工具；页面只持有白名单桥；单视图崩溃不牵动其他视图与壳层。
11. **依赖方向**：views 只消费页面解析 / 页面会话 / 变更订阅 / 命令四类契约；views 不 import pi；agent 不 import Electron。
12. **安全与退出**：页面在命令通道上被拒；凭证不出主进程；流式中退出不挂起；用户状态、会话文件与结构化数据无半写。
