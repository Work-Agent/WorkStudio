# Agent 域技术方案（agent-design.md）

> 定位：按 **pi 的集成模型**（资源轴 + 注册轴）把 WorkStudio 接上去，并以资源管道（URA）作为资源内容的唯一控制面。
>
> 架构前提见 [`architecture.md`](./architecture.md)；views 如何消费本域契约见 [`views-design.md`](./views-design.md) §1.5。

## 一、集成模型：pi 的两条轴

pi 只有两条扩展轴，WorkStudio 不再另造插件系统：

| 轴                   | 载体                                         | 类别                                                                                                                   | 由谁收集                                  |
| -------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| **资源轴**（声明式） | 包清单的 `pi` 字段 / 约定目录 / 设置里的路径 | extensions · skills · prompts · themes                                                                                 | 包管理器扫文件 → 资源装载器加载           |
| **注册轴**（命令式） | 扩展模块执行时的代码调用                     | tools · commands · shortcuts · flags · handlers · messageRenderers · entryRenderers · markdownTransformers · providers | 扩展工厂运行时填充 Extension 对象里的 Map |

两条轴的性质不同，不能互相替代：

- **资源轴是「装载」**：声明在哪、有什么文件；不执行代码，只产出可枚举的资源。
- **注册轴是「执行」**：扩展工厂在运行时被调用，把能力塞进 Map；同一会话换代重跑工厂。

**WorkStudio 的接入原则**：能力一律走这两条轴，不新增第三种插件形态。

术语：**Plugin（插件）**是 WorkStudio 自己的概念——安装与能力单元（清单 + 页面 + 资源实现 + 技能 / 提示 / 主题），由我们管理；**Extension（Pi 扩展）**是 pi 的概念——扩展模块，由 pi 装载并在注册轴注册会话侧能力。插件可携带 0..N 个 Extension，Extension 也可直接来自 pi 包。

## 二、接入点

### 2.1 资源轴：我们放什么

| 资源       | 载体                            | WorkStudio 的内容                                                             |
| ---------- | ------------------------------- | ----------------------------------------------------------------------------- |
| extensions | 包清单 `pi` 字段 / 设置里的路径 | 内置 harness 扩展 · 内置 URA 扩展 · 第三方能力包                              |
| skills     | 包目录 / 约定目录               | 内置技能 · 插件技能                                                           |
| prompts    | 包目录                          | 内置提示模板                                                                  |
| themes     | 包目录                          | 主题资源（桌面主题另有自己的分发，见 [`views-design.md`](./views-design.md)） |

- **扫描顺序**：内置包 → 用户包（按包名排序）→ 设置声明的路径；后加载覆盖先加载（pi 语义），每次覆盖记诊断。
- **装载来源**：插件目录与 pi 包（`pi` 字段 / 设置路径）都经 pi 的资源装载链；安装记录写设置，依赖落应用自持目录。
- **应用不定义新的资源类型**：页面入口、格式实现都不是「资源」，它们是注册轴的产物（见 2.2）。

### 2.2 注册轴：我们注册什么

扩展工厂执行时拿到 **pi 上下文**（注册 pi 能力）；URA 注册不是第三种机制，而是同一注册轴上另一组 API：能力包通过 WorkStudio SDK 在工厂执行期调用 URA 注册（模块导入即可，不改 pi 的工厂签名）。

| 注册项                           | 谁注册                       | 消费方     |
| -------------------------------- | ---------------------------- | ---------- |
| 7 个资源管理型工具 + 操作型工具   | harness 扩展                 | 模型       |
| 命令 / 快捷键 / 标志 / 事件钩子  | harness 扩展（应用命令）     | 会话运行时 |
| 消息 / 条目渲染器、供应商        | 内置或第三方扩展             | 运行时     |
| 来源实现（transport）            | 能力包扩展（含内置本地来源） | 资源管道   |
| 格式实现（codec）                | 能力包扩展                   | 资源管道   |
| 结构化数据（store）              | 能力包扩展                   | 资源管道   |
| 投影（agent / editor consumer）  | 能力包扩展                   | 资源管道   |
| 页面（渲染器 / 编辑器 / 设置页） | 能力包扩展                   | 视图宿主   |
| 集合（侧栏分组）                 | 能力包扩展                   | 侧栏投影   |
| 动作（地址栏工具条）             | 能力包扩展                   | 壳层工具条 |

规则：

- **URA 服务先于运行时构造**：URA 注册表是应用级的；扩展工厂第一次执行时完成注册。
- **注册幂等**：pi 每次会话换代都重跑工厂；同键、同实现的重复注册被忽略，不重复入表。
- **冲突按 pi 的 Map 语义**：同键后注册者胜出，内置最早、用户包覆盖内置；覆盖与忽略都进诊断。用户配置可禁用包或指定实现。
- **注册期校验**：来源声明的格式提示、格式声明的文档类型与补丁形态、投影的出口、页面的匹配键——不兼容的注册被拒绝并诊断，不进入分发表（内置包不兼容视为构建错误，直接失败）。

### 2.3 清单与入口（package.json）

插件就是 npm 包，清单字段与代码入口都在 `package.json`，不再有单独的 manifest.json。**一个插件最多两个页面**：`page`（渲染器页，可选）与 `settings`（设置页，可选），至少一个。设置类插件只声明 `settings`。

```json
{
  "name": "@workstudio/plugin-docx",
  "version": "1.2.0",
  "description": "DOCX 阅读与编辑",
  "author": "work-studio",
  "exports": {
    "./ura": "./dist/ura.js",
    "./pi": "./dist/pi-extension.js"
  },
  "workstudio": {
    "id": "docx",
    "label": "DOCX",
    "page": "pages/index.html",
    "settings": "pages/settings.html"
  }
}
```

`./ura` 入口在模块求值时调用注册接口：

```js
import { registerCodec, registerConsumer } from "@workstudio/sdk";

registerCodec({ formatHints: ["ooxml"], docType: "ooxml-doc@1", patchKind: "bytes", decode, locate, encode });
registerConsumer({ docType: "ooxml-doc@1", kind: "editor", surface: "docx-editor", project });
```

- 注册接口一共六个：`registerTransport` · `registerCodec` · `registerStore` · `registerConsumer` · `registerCollection` · `registerViewAction`。
- `page` 不再由 consumer 声明：它是渲染器页；没有渲染器页的插件只声明 `settings`。
- 设置页是独立的第二个页面（`settings`），适用于设置类插件（偏好设置 / 模型配置等）；名称沿用 `workstudio.label`。
- **页面资源白名单**：两个页面只能装载各自目录（含子目录）下的资源，其余路径一律 403，并挡路径穿越；确有额外资源目录时才写 `webAccessible` 覆盖默认值。

加载流程（每个插件）：

```
① 扫描：package.json 带 workstudio 字段
② import exports["./ura"]：模块求值时插件自己调用 registerXXX
   （只注册自己提供的能力：只有格式就只调 registerCodec，等等）
③ import exports["./pi"]：交给 pi 的资源装载链
④ workstudio.page / workstudio.settings：交给视图宿主，按资源白名单装载
```

旧清单字段的归位：

| 旧字段                                       | 现在                                              |
| -------------------------------------------- | ------------------------------------------------- |
| `id`                                         | `workstudio.id`（缺省用包名）                     |
| `name` / `version` / `description` / `author` | `package.json` 同名标准字段                       |
| `config { id, label, src }`                  | `workstudio.settings`（设置页路径；名称用 `workstudio.label`） |

### 2.4 信任边界（按 pi 的模型，不虚构隔离）

- **扩展跑在主进程，与进程同权限**：这是 pi 的生态模型。能力包（来源 / 格式 / 投影 / 页面）也是扩展，因此安装即授予进程权限，安装前必须明示。
- **URA 收敛的是 API，不是操作系统权限**：URA 只向扩展提供「统一标识 + 内容 + 补丁」这组入口，不提供写通道对象；但主进程代码原则上仍可自行碰文件——所以信任边界在**安装**，不在运行时。
- **页面跑沙箱渲染进程**：无 Node、无裸 IPC、只能调白名单命令；页面拿不到视图句柄、版本号与结构化数据。
- **工具面不让插件扩**：工具只由 harness 注册；插件不能注册工具，避免模型能力面被第三方改写。

## 三、Harness 与资源管道（URA）

### 3.1 控制模型

harness 是自持能力层；本节讲它的资源访问部分（URA），系统提示 / 工具 / 技能 / 浏览器见 §四。

URA 是资源内容的**唯一读写入口**：人（界面）、AI（工具）、插件（实现）都只拿统一标识，不拿路径与句柄。资源的副作用只发生在来源实现里。

```
读：scheme → 来源（transport）→ 原始内容 + 格式提示 + 版本
             → 格式（codec）→ 结构化文档 + 文档类型
             → 数据（store）→ 可查询结构化数据（派生 · 版本戳）
             → 出口（consumer）→ 文本投影（agent）/ 页面入口 + 结构标识（editor）

写：变更（整篇 / 锚定）→ 定位（用投影映射反查）→ 编码（最小补丁）
                     → 来源提交 → 新版本 → 数据更新 → 广播
```

| 控制项   | 机制                                                           | 保证                             |
| -------- | -------------------------------------------------------------- | -------------------------------- |
| 物理访问 | 只有来源实现触达文件 / 网络 / 服务；管道按协议路由到已注册实现 | 页面拿不到句柄、路径、连接       |
| 寻址     | 来源 + 类型 + 路径 → 统一标识；物理路径不出域                  | 换来源不改上层引用               |
| 准入     | 按调用方（人 / agent / system）与来源能力判定读写              | 越权在门面内被拒，不落到来源实现 |
| 解释     | 格式实现按声明处理；未知或失败降级 raw                         | 不猜格式、不静默失败             |
| 可见性   | 模型侧只给 schema；页面侧拿可编辑投影                          | 行数据不进模型上下文             |
| 并发     | 写会话 + 分片队列 + 版本校验                                   | 同键串行，过期写拒绝             |
| 生命周期 | 打开 → 解析 → 缓存 → 失效 → 释放；缓存按版本失效               | 不重复解码，不返回过期内容       |
| 传播     | 所有写经同一管线 → 解析缓存 / 结构化数据 / 订阅一致            | 不存在第二份真相                 |
| 审计     | 每次读 / 写 / 降级记录来源、调用方、链路                       | 可追溯、可复现                   |

### 3.2 门面与工具

| 族 | 操作                                                           | 说明                                 |
| -- | -------------------------------------------------------------- | ------------------------------------ |
| 读 | read · grep · find · ls · query                                | query 走结构化数据；其余读内容或清单 |
| 写 | edit / write（单步）· stage / apply / commit / abort（写会话） | 单步 = 写会话的三步合成              |
| 听 | watch · unwatch                                                | 订阅资源与范围的变更                 |

**资源管理型工具**固定 7 个，与资源类型无关，全部经 URA 门面；**操作型工具**（浏览器族、业务动作）经各自契约注入，不进 URA：

| 工具  | 语义                                         | 依赖的管道段               |
| ----- | -------------------------------------------- | -------------------------- |
| read  | 读内容（全文 / 行窗口 / 清单 / 元信息）      | 来源 + 格式 + 出口         |
| write | 整篇写入（新建 / 覆写）                      | 来源 + 格式                |
| edit  | 锚定替换                                     | 来源 + 格式 + 出口         |
| grep  | 内容检索                                     | 结构化数据（无则来源扫描） |
| find  | 按模式查找路径                               | 结构化数据（无则来源清单） |
| ls    | 列出目录 / 容器内容                          | 来源                       |
| query | 结构化查询（只对声明了结构化数据的文档类型） | 结构化数据                 |

- **人与 AI 同名同义**：同一门面名、同一实现；操作型工具（浏览器族等）不走门面，不列在上述表中——它们不依赖管道段，经契约注入（见 §4.4）。
- **门面只做编排**：不含格式解释与来源访问。
- **写会话是草稿**：暂存期不落盘、不进投影、不进模型上下文；提交才产生资源写入。

### 3.3 分发与降级

- 分发只查表：协议 → 内容类型 × 格式提示 → 文档类型 → 出口。
- **不做内容探测、不试错其他组合**：确定性优先。
- 任一环缺失或失败 → 降级 raw（原始内容 + 兜底页），降级点记入诊断。
- 新建资源的类型指定顺序：显式类型提示 > 扩展名推断 > 用户配置 > 仅 raw 写入。

### 3.4 结构化数据与同步

- **定位**：管道第四段；按文档类型注册；内置 SQLite（邮件、表格、业务数据），纯文本类可缺省。
- **不变量**：派生、可重建、**永不为真值**；每行带版本戳（资源版本 · 格式版本 · schema 版本）；只由同步与提交写入；工具只读。
- **同步**：拉（远端变更游标 / 本地文件监听 → 解码 → 写入）· 推（本地提交 → 编码 → 来源提交）；失败进待重试队列，超时标记待对账。
- **数据依据**：`grep / find / ls / query` 以结构化数据为据；无则退回来源扫描；都不支持则明确失败。
- **数据轨**：模型侧只拿 schema 与 query（agent 的 read 全文路径关闭）；页面侧按投影展示与编辑（行数据可进页面，不进模型）。
- **重建**：格式 / schema 版本变化 → 标脏 → 后台重建；全量重扫是兜底。

### 3.5 写入控制

| 项       | 规则                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 保存模式 | 页面声明 + 用户偏好覆盖：手动 / 实时 / 失焦；只决定提交时机            |
| 队列     | 按资源键分片，同键串行、跨资源并行；入队轻校验，出队权威校验           |
| 版本     | 严格（位置敏感，锚点或基线必须匹配）· 幂等（状态变更只需未失效）       |
| 结果     | 已提交 / 冲突 / 超时 / 待对账 / 部分成功                               |
| 冲突     | 返回基线 / 当前 / 我的三份内容与逐处状态；由发起方选重放 / 弃稿 / 覆盖 |
| 合并     | 不自动合并；数据轨拒绝强制覆盖                                         |

**无反向编解码层**：编码直接产出传输层可消费的补丁；写入后失效解析缓存、更新结构化数据、广播变更。

### 3.6 变更传播

| 维度     | 定义                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 对象     | 资源（单条）· 范围（分组 / 目录 / 来源）                                                      |
| 事件     | 内容级（内容变更 · 版本递增）· 结构级（增 / 删 / 重命名 / 移动）· 状态级（写会话开启 / 提交） |
| 来源     | 全部写路径的同一出口：工具写 · 提交 · 外部盘上变更 · 远端变更游标                             |
| 送达     | 增量事件 + 版本；不承诺不漏，缺口用重读 / 快照对齐                                            |
| 生命周期 | 随会话 / 页面 / 写会话存活；显式取消或销毁即回收；不落盘                                      |

### 3.7 出口与页面契约

| 出口 | 形态                                                | 职责                                                                |
| ---- | --------------------------------------------------- | ------------------------------------------------------------------- |
| AI   | 7 个资源管理型工具 + 操作型工具（harness 注册）       | 资源工具 → 门面；操作型走契约；确认 / 截断 / 错误格式化由钩子统一处理；插件不注册工具 |
| 页面 | 页面会话（打开 → 就绪 → 投递 → 脏态 / 提交 → 释放） | 页面只声明入口；视图宿主独占生命周期与几何                          |

页面契约（本域提供给 views 的部分）：

- **页面解析**：文档类型 / 扩展名 → 入口、声明动作、可访问资源白名单；
- **页面会话**：投递、外部变更、触发保存、提交（含冲突结构）、释放；
- **可见性**：数据轨向页面提供可编辑投影，但不向模型投递行数据；
- **不提供**：视图句柄、版本 token、队列、结构化数据内部访问。

两个出口共享管道、定位、版本、降级与错误语义；不共享调用形态、载荷形状、生命周期。

### 3.8 基石：工具与上下文

工具与上下文都是 URA 的产物，不是两套旁路：

- **资源管理型工具 = 门面的薄封装**：7 个工具不含 IO、不含格式解释，只做「解参数 → 调门面 → 格式化结果」；操作型工具经各自契约注入，同样不开放注册。
- **上下文 = URA 的资源**：AGENTS.md 等项目指令与资源地图，全部经统一标识发现（ls / find）→ 读取（read）→ 投影（agent 出口）→ 经 pi 的项目文件注入口送入上下文；内容变化经 watch 失效并重新注入。
- **一条硬规则**：进入模型上下文的任何内容都必须有资源身份（标识 + 版本 + 可见性判定）；不允许绕过管道直接读文件塞进提示。
- **结果**：换来源不改工具与提示，换格式不改工具与提示；数据轨（schema-only）在工具与上下文两侧同时生效。

## 四、Harness 的其余能力

harness 是内置扩展（资源轴装载），在注册轴上注册能力。

### 4.1 系统提示

提示由 URA 的产物组装，不各自维护旁路：

1. **角色与边界**：工作区业务操作助手；不写代码、无 shell；只编排确定性工具。
2. **资源地图**：由 URA 投影生成（目录 / 分组 / schema），注入上下文；先看地图，再按需取用。
3. **项目指令**：AGENTS.md 等上下文文件作为 URA 资源读取与投影，自带版本；变化经变更订阅重新注入。
4. **数据轨铁律**：模型侧永不暴露行数据（只给 schema），查询走工具；页面侧按投影展示与编辑；机制由管道保证。

语言约束：始终以中文回答（与用户语言无关）。

### 4.2 工具

工具全部在本扩展内注册（见 §3.2），分两类：**资源管理型**（read / write / edit / grep / find / ls / query）是门面的薄封装；**操作型**（浏览器族、业务动作）经各自契约注入。pi 内置工具停用；确认 / 截断 / 错误格式化由钩子统一处理。

### 4.3 技能

- **装载**走资源轴：包声明的技能目录进入装载；命名与诊断沿用官方。
- **激活**：选中集为空 = 全量注入；有选中时按名过滤提示段与清单。
- **展示**：清单（名称 / 描述 / 路径 / 作用域 / 来源 / 仅手动）+ 装载诊断，供技能页使用；选中集落用户状态。
- **管理**：技能页可过滤、打开文件、查看诊断、重新装载；激活集合在输入区选择。

### 4.4 浏览器自动化

操作型工具的一种：不经过 URA，只依赖实现无关契约。

- 工具层只依赖实现无关契约（打开 / 导航 / 读取 / 点击引用 / 截图 / 标注可交互元素）；驱动由装配层注入。
- 作用实例 = 当前激活的网页标签；无可用面板时明确失败（不静默开新窗口）。
- 页面新窗口请求由视图宿主收编为应用内新标签。

## 五、会话与事件

### 5.1 会话生命周期

| 操作               | 语义               | 是否换代   |
| ------------------ | ------------------ | ---------- |
| 新建 / 切换        | 创建或打开并绑定   | 是（重绑） |
| 分支               | 从条目分叉出新会话 | 是（重绑） |
| 提示 / 插话 / 追加 | 送入模型或插入消息 | 否         |
| 中断 / 压缩 / 历史 | 终止、压缩、读取   | 否         |

换代 = 会话对象替换，必须按序完成：**事件订阅切换 → 扩展绑定（UI 上下文 / 运行模式 / 命令上下文 / 退出回调）→ 状态上报（换代原因）**。换代期间会话不可用，只由明确原因触发（模型目录变更、工作区切换、扩展运行器重启），流式中延后到本轮结束。

工具与命令随运行时重建而重注册；URA 注册表是应用级，重跑工厂时幂等忽略。

### 5.2 事件桥

```
会话订阅 → 官方线格式 → 合帧（窗口内同槽取最新）→ 事件帧（单调序号）→ 广播
```

- **合帧槽**：消息更新 · 工具执行更新 · 命令执行更新；定序事件不合并，沿用原序号槽位。
- **pi 事件与应用事件共用同一序列**：会话创建、换代、状态变更、错误。
- **重建握手**：快照返回游标；检测缺口即重新握手重建，不做增量回放。
- **唯一出口**：模型与工具的全部过程只经事件桥上行。

### 5.3 扩展 UI 上下文

| 族         | 内容                                                    |
| ---------- | ------------------------------------------------------- |
| 对话框     | 选择 / 确认 / 输入 / 编辑（请求 + 应答 + 超时）         |
| 状态       | 通知 · 状态文本 · 工作态 · 小组件 · 标题 · 隐藏思考标签 |
| 编辑器镜像 | 文本镜像推送 + 同步读取应答                             |
| 命令上下文 | 等待空闲 · 新建会话 · 分支 · 树导航 · 切换会话          |
| 退出回调   | 退出前冲刷会话域并标记退出意向                          |

约束：对话框走浮层（模态必须在原生层）；请求-响应用待答表 + 超时回落；UI 状态在主进程留快照，握手重放。

## 七、存储与配置

### 7.1 会话存储与索引

- **落盘**：官方 JSONL；目录解析优先级为设置 → 默认每工作区会话目录。
- **列表**：标题 / 预览 / 时间由会话文件解析，按时间倒序。
- **懒落盘**：空会话不建文件，首条消息才落盘。
- **删除**：删文件 + 从打开集合移除；删的是当前会话则先新建空会话。
- **重命名**：当前会话直接改名；其余以元信息追加。
- **目录切换**：触发会话域重建，旧文件不迁移。

### 7.2 模型与配置

| 文件     | 内容                                                | 写入命令                     |
| -------- | --------------------------------------------------- | ---------------------------- |
| 模型目录 | 供应商（标识 / 名称 / 地址 / 协议 / 模型清单）      | 供应商与模型的保存 / 删除    |
| 设置     | 默认供应商与模型 · 档位记忆 · 压缩与重试 · 会话目录 | 模型与档位变更 · 设置域命令  |
| 凭证     | 供应商凭证（官方凭证格式）                          | 登录 / 登出 · 清除运行时密钥 |

- **零默认值**：界面不写死供应商与模型；未配置是合法状态，输入区禁用并给出配置入口。
- **供应商目录 = 官方组合结果**：内置与自定义同列；凭证状态由官方链解析。
- **密钥不落模型目录**：运行时覆盖仅内存，可撤销。
- **写盘守卫**：写入后以真实加载链验证，期望项未被收录则回滚并报错。
- **设置契约**：两层原始值 + 深度合并的生效值 + 落盘位置；置空即删键并清理空父级；未列入表单的字段原样保真。
- **即时生效**：模型与档位立即作用于会话；模型目录变更触发换代；凭证变更刷新可用性。

### 7.3 工作区

- **自描述**：每工作区一份描述（路径 / 创建时间 / 最近打开）；标识由路径派生。
- **当前 = 最近打开者**（路径存在；不存在落到次新），没有第二份「当前选中」状态。
- **首装**：创建默认工作目录并注册。
- **切换即换代**：重建运行时，重绑资源管道 / 用户状态 / 浏览器策略 / 会话索引；界面经事件收敛。
- **隔离粒度**：会话、用户状态、结构化数据、派生数据、工作区层设置按工作区隔离；模型目录与凭证属应用级。

### 8.2 社区与安装

- **两种来源**：WorkStudio 插件（我们的清单与目录：页面 / 资源实现 / 技能）与 pi 包（extensions / skills / prompts / themes）。安装记录写设置，依赖落应用自持目录，装载走官方链。
- **社区目录**：官方画廊无公开 JSON 接口，按服务端渲染页抓取（搜索 / 类型过滤 / 分页）。
- **管理页即页面**：社区浏览、已安装、已加载资源、本机插件四块。
- **生效时机**：安装 / 卸载后热重载资源（流式中延后到本轮结束），不重启。
- **隔离**：包配置写应用自持目录，不污染用户全局 pi 环境。

### 8.3 页面数据面

- 页面只持有语义化桥：白名单命令 + 视图总线；无 Node、无裸 IPC。
- 主进程校验来源后按映射转发到**同一条命令实现**；未列入映射的命令不存在。
- 页面不可触达视图域命令与用户状态写命令；设置类页面需要的会话 / 工作区 / 存储 / 资源命令按白名单放行。
- 页面偏好存本插件分区（与页面同源）。

## 九、诊断与验收

### 9.1 错误与可观测

| 场景                    | 处理                                             |
| ----------------------- | ------------------------------------------------ |
| 提示词执行异常          | 捕获 → 以错误事件上报 → 结束流式执行             |
| 资源装载 / 扩展执行失败 | 进加载诊断；该扩展不进入运行时；不阻塞其余扩展   |
| 注册校验失败            | 拒绝该注册并诊断（内置包视为构建错误）           |
| 模型调用失败            | 官方重试（可配）；错误进消息流尾部，会话回到空闲 |
| 配置写盘失败            | 回滚文件；命令返回失败；页面行内错误             |
| 写入冲突 / 超时         | 返回冲突或待对账状态；不自动合并、不自动重试     |
| 页面数据面拒绝          | 非页面来源拒绝；未映射命令不存在                 |
| 退出时有流式执行        | 先清队列并中止，再销毁运行时                     |
| 启动链异常              | 日志 + 界面错误页；不进入半可用状态              |

观测项：包扫描与装载轨迹 · 扩展工厂执行 · 注册覆盖与忽略 · 分发链路（协议 → 格式 → 文档类型 → 出口）· 降级点 · 缓存命中 · 队列快照 · 版本冲突 · 页面资源请求 · 权限拒绝与审计。

### 9.2 验收要点

1. **同源启动**：工具集合 = harness 注册的 7 个资源管理型工具 + 操作型工具（无官方内置工具），默认模型与官方命令行读同一条设置链。
2. **按 pi 接入**：新增能力只经资源轴（包声明）与注册轴（扩展工厂注册），不存在第三套插件清单或加载器。
3. **资源唯一入口**：人 / AI / 页面都经门面访问资源；页面无 Node；工具不直连来源。
4. **数据轨**：AI 侧读数据资源只返回 schema（页面不在此限），AI 写 / 编辑拒绝；shell 类工具在任何清单里都不存在。
5. **写控制**：同键串行；过期写返回冲突并带三份内容；超时标记待对账；冲突不自动合并。
6. **注册语义**：同键后注册者胜出且可解释；内置 << 用户包；注册校验不兼容即拒绝。
7. **零框架改动扩展**：只写格式与投影即可新增格式；只写来源实现即可新增来源；工具列表不变。
8. **管道降级**：任一环失败降级 raw 并记录降级点；不出现静默空白页。
9. **结构化数据**：删除后由来源重建并恢复查询与列表；重建期间读走直通不返回空。
10. **退出干净**：流式执行中退出不挂起；用户状态、会话文件与结构化数据无半写。
11. **上下文同源**：AGENTS.md 与资源地图经 URA 发现 / 读取 / 投影；外部改动后在下一轮提示中生效，不出现「文件已变、提示未变」。
